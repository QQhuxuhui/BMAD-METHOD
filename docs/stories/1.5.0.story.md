### 专家库README.md索引格式规范

每个专家库的README.md必须遵循以下格式：

```markdown
# {Library Name}

## 概述

{库的简要说明}

## 知识目录

### {分类1}

- **{知识点标题}** [@{文件路径}]
  描述: {简要描述}

### {分类2}

- **{知识点标题}** [@{文件路径}]
  描述: {简要描述}

## 使用场景

- 场景1: {描述}
- 场景2: {描述}

## 参考资料

- {外部参考链接}
```

**关键要素**:

1. **@引用路径**: 每个知识点必须有`@{相对路径}`标记，用于溯源
2. **结构化分类**: 使用二级标题组织知识分类
3. **简要描述**: 每个知识点提供1-2句话的描述
4. **使用场景**: 明确该库的适用场景

### 两阶段提示词框架设计

**Stage 1: 任务理解和知识检索**

输入:

- 用户任务描述
- 可用专家库列表

输出:

```json
{
  "task_understanding": {
    "problem_type": "string",
    "key_requirements": ["req1", "req2"],
    "constraints": ["constraint1"]
  },
  "knowledge_needed": [
    {
      "library": "algorithm-library",
      "category": "metaheuristics",
      "reason": "需要选择合适的优化算法"
    }
  ]
}
```

**Stage 2: 知识应用和输出生成**

输入:

- Stage 1的输出
- 检索到的专家知识内容

输出:

```json
{
  "solution": {
    "approach": "string",
    "justification": "string",
    "references": ["@algorithm-library/metaheuristics/ga.md"]
  },
  "details": {
    // 具体的输出内容（因智能体而异）
  }
}
```

### 风险和缓解

**风险1: 专家库文件路径引用需要调整（中等风险）**

- 缓解: 编写自动化脚本批量更新@引用路径
- 验证: 使用正则表达式检查所有@引用的有效性

**风险2: README.md格式不统一（低风险）**

- 缓解: 提供标准模板，人工review每个README.md
- 验证: 编写格式验证脚本

**风险3: 知识库内容可能需要补充（低风险）**

- 缓解: 先迁移现有内容，后续在使用中逐步完善
- 策略: 每个智能体实现时review对应库的完整性
