## 触发场景

当约束建模存在以下情况时使用此模板:

1. 约束类型不明确 (硬约束 vs 软约束)
2. 约束参数缺失或模糊
3. 约束冲突需要用户仲裁
4. 隐含约束需要确认

## 对话结构

### 步骤1: 呈现分析结果

AI呈现已识别的约束:

- 明确识别的约束类型
- 约束参数和限制
- 约束严格程度 (硬/软)

### 步骤2: 提出不确定项

AI请用户确认约束细节:

- **硬软属性**: 违反约束是否可接受
- **约束参数**: 具体数值或范围
- **优先级**: 多约束时的重要程度
- **惩罚方式**: 软约束的惩罚函数

### 步骤3: 解析用户反馈

- **硬软选择**: 硬约束/软约束/可违反
- **参数输入**: 具体数值
- **优先级排序**: 1, 2, 3...
- **惩罚描述**: 惩罚力度说明

### 步骤4: 更新模型

更新TenElementModel的constraints:

```python
{
    "constraint_type": "用户确认的约束类型",
    "is_hard": true/false,
    "parameters": {用户提供的参数},
    "priority": 1-5,
    "penalty_function": "用户确认的惩罚方式"
}
```

## 模板示例

### 示例1: 硬软约束确认

```yaml
AI: |
  ## 🤝 约束类型确认

  **已识别的约束**:
  - ✅ 时间窗约束 (客户有指定的服务时间段)
  - ✅ 容量约束 (车辆有载重限制)

  ### ❓ 需要您确认约束的严格程度

  **问题 1: 时间窗约束**
  如果无法在客户指定的时间窗内到达，是否可接受?

  1. **硬约束** - 绝对不可违反
     - 必须在时间窗内到达
     - 违反则方案不可行

  2. **软约束** - 可违反但有惩罚
     - 允许延迟到达
     - 每延迟1分钟惩罚 ___元 (请填写)

  **问题 2: 容量约束**
  如果车辆略微超载，是否可接受?

  1. **硬约束** - 绝对不可超载
  2. **软约束** - 允许超载但有惩罚

  请说明您的约束要求。

User: 时间窗是硬约束，容量约束可以略微超载，每超载1kg惩罚5元

AI: |
  ✅ 约束已确认:
  - 时间窗约束: **硬约束** (不可违反)
  - 容量约束: **软约束**
    - 允许超载
    - 惩罚: 5元/kg

  我将基于这些约束设置生成约束处理代码。
```

### 示例2: 约束参数确认

```yaml
AI: |
  ## 🤝 约束参数确认

  **已识别的约束**:
  - ✅ 连续工作天数限制

  ### ❓ 需要您提供约束参数

  **问题: 连续工作天数上限**
  员工连续工作不超过多少天？
  - 常见设置: 3天、5天、7天
  - 请输入具体天数

  **问题: 是否允许例外**
  在紧急情况下是否允许违反此约束?
  1. 不允许 (硬约束)
  2. 允许但需额外补偿 (软约束)

User: 连续5天，允许例外但每超过1天额外补偿500元

AI: |
  ✅ 约束已确认:
  - 连续工作天数: ≤ 5天
  - 约束类型: 软约束
  - 惩罚: 500元/天 (超出部分)

  我将此约束纳入排班模型。
```

### 示例3: 约束冲突仲裁

```yaml
AI: |
  ## 🤝 约束冲突仲裁

  **检测到约束冲突**:

  **冲突: 完成时间 vs 成本控制**
  - 约束1: "所有订单必须在今天完成" (时间约束)
  - 约束2: "加班成本不能超过预算" (成本约束)

  **分析结果**:
  - 要满足时间约束，需要加班，但会超出成本预算
  - 要满足成本约束，部分订单将延迟到明天

  ### ❓ 请选择优先级

  1. **时间优先** - 所有订单今天完成，接受成本超支
  2. **成本优先** - 控制成本，接受部分订单延迟
  3. **平衡方案** - 紧急订单今天完成，普通订单延迟

  请选择或说明您的倾向。

User: 平衡方案，优先保证VIP客户和紧急订单

AI: |
  ✅ 约束优先级已确认:
  - P1 (最高): VIP客户和紧急订单的时间约束
  - P2: 成本控制约束
  - P3: 普通订单的时间约束

  我将按此优先级调整调度方案。
```

2. **提供基准**: 给出行业常见的约束参数值
3. **冲突可视化**: 用对比表格呈现约束冲突
4. **分级处理**: 复杂约束分步确认，避免信息过载
