## 💡 关键设计决策

| 决策                           | 理由                                                                         |
| ------------------------------ | ---------------------------------------------------------------------------- |
| 三列布局（与 P2 三道墙对称）   | 视觉语法上形成 "问题 3 堵墙 → 解法 3 机制" 的叙事闭环                        |
| 每列只给"1 图 + 1 句 + 1 数字" | 一页三机制，克制信息量是第一要务——宁愿讲少一点讲透，也不要全讲完糊成一团     |
| 机制③ 用"三件套合一"表达       | Todo / Guardrails / 持久化三件独立讲占地太大；视觉上合成"三道护栏"更有整体感 |
| 底部点题用"三道解法"押韵       | **经济账 / 协作账 / 可靠性账** 三个词对业务评委是秒懂的业务语言              |
| 不标"回应 P2 墙 X"             | 叙事闭环通过口头讲述点出，PPT 上不再堆字                                     |

**整体风格**：白色系商务正式 · 低密度高留白 · 强理性弱装饰

**配色规范**

| 用途     | 色值      | 用法                     |

| 副文字   | `#4A5568` | 中灰 · 副标题 / 注释     |

| 点缀金色 | `#D69E2E` | 仅用于 🏆 国赛图标       |

**字体规范**

- 中文：思源黑体 / 微软雅黑（兜底）
- 英文 & 数字：Inter / Helvetica Neue（兜底）
- 主标题：大字号 · 加粗 · 深墨灰
- 副标题：次级字号 · 细体 · 中灰
- 数字亮点：超大字号 · 加粗 · 深蓝

**版式规范**

- 每页四角留白 ≥ 5%
- **克制使用 emoji**：保留功能性标识，删除装饰性表情；优先线框 icon（Feather / Tabler Icons 风格）
- 分隔元素：1px 浅灰细线，避免厚重底纹
- 对齐：统一居中或左对齐，避免混用

**本页视觉重点（P4 三机制）**

- **三列对称**布局（视觉与 P2 三道墙呼应——形成"问题 3 堵墙 → 解法 3 机制"的叙事闭环）
- **机制 ① 金字塔图**：三层用**同色不同明度**渐变（浅蓝 → 中蓝 → 深蓝 `#1A365D`）

## 🎤 口头讲词（~80 秒）

> "**Agent as Doc 能成立，靠的是三套机制：**
>
> 第一，**Sidecar 按需加载**。智能体是三层结构：最核心是 500 tokens 的角色定义，外面是 5K 的知识索引，最外层才是按需加载的具体模块——这是 Token 节省 75-87% 的技术根源。
>
> 第二，**十要素模型**。调度问题无论多复杂，我们用 10 个要素就能完整描述——决策变量、参数、约束、目标、算法……这是 7 个专家能协作的前提：**大家说的是同一种语言**。
>
> 第三，**反 AI 幻觉三件套**。这个对业务落地最关键——**Todo 清单**把需求转成执行合同防偏离；**Guardrails 强引用**要求每个输出都附来源防虚构；**状态持久化**让长流程断点续传不丢数据。三道护栏同时工作，保住了 92% 代码可用率。
>
> 一句话：**按需加载解经济账，统一建模解协作账，反幻觉解可靠性账**。"

## 📌 要点索引

**机制 ① Sidecar 按需加载**：三层加载（500t 角色 + 5K 索引 + 2-5K 模块）→ 解决 Token 经济账

**机制 ② TenElementModel 十要素模型**：10 要素（决策变量 / 参数 / 约束 / 目标 / 算法 / 时间 / 不确定性 / 求解配置 / 输入 / 输出）→ 解决多专家协作共识

**机制 ③ 反 AI 幻觉三件套**：

- 📋 **Todo 执行合同**（需求转执行合同，偏离检测相似度 < 0.60）
- 🔒 **Guardrails 强引用**（所有输出必须附 @ 引用，禁止无根据推断）
- 💾 **状态持久化 + 续传**（每 Phase 强制落盘，断点续传零上下文丢失）
