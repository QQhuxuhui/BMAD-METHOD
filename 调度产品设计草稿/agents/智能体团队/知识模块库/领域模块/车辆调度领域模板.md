## 🚛 领域知识本体

### 车辆调度核心概念

```yaml
基本要素:
  车辆 (Vehicle):
    - 载重能力: 重量限制、体积限制
    - 运行特性: 速度、油耗、可靠性
    - 工作时间: 班次时间、休息要求
    - 成本结构: 固定成本、变动成本

  客户 (Customer):
    - 需求量: 货物重量、体积、件数
    - 地理位置: 坐标、地址、区域
    - 时间要求: 时间窗、服务时间
    - 服务等级: 优先级、特殊要求

  路网 (Network):
    - 节点: 仓库、客户、中转站
    - 边: 道路、距离、行驶时间
    - 交通状况: 拥堵、限行、路况
    - 成本: 过路费、燃料费

  仓库 (Depot):
    - 位置: 地理坐标、覆盖范围
    - 容量: 存储能力、装卸能力
    - 时间: 开放时间、作业时间
    - 资源: 装卸设备、人员配置

问题类型:
  VRP (Vehicle Routing Problem):
    - 基本车辆路径问题
    - 目标: 最小化总行驶距离

  CVRP (Capacitated VRP):
    - 有容量限制的车辆路径问题
    - 约束: 车辆载重限制

  VRPTW (VRP with Time Windows):
    - 带时间窗的车辆路径问题
    - 约束: 客户时间窗限制

  MDVRP (Multi-Depot VRP):
    - 多仓库车辆路径问题
    - 特征: 多个配送中心

  SDVRP (Split Delivery VRP):
    - 允许分批配送的车辆路径问题
    - 特征: 客户需求可分割
```

## 🎯 领域特定算法知识

### 构造启发式算法

```yaml
节约算法 (Savings Algorithm):
  基本思想:
    - 计算两两客户合并的节约值
    - 按节约值从大到小排序
    - 逐步合并形成路径

  节约值计算: S(i,j) = D(0,i) + D(0,j) - D(i,j)
    其中 D(i,j) 为客户i到j的距离

  算法步骤: 1. 计算所有客户对的节约值
    2. 将节约值按降序排列
    3. 依次考虑每个客户对
    4. 如果合并可行则执行合并
    5. 检查容量和时间约束

  适用场景:
    - 中小规模问题
    - 简单约束条件
    - 快速解决方案需求

最近邻算法 (Nearest Neighbor):
  基本思想:
    - 从仓库开始
    - 每次选择最近的未访问客户
    - 直到车辆满载或无可访问客户

  算法步骤: 1. 当前位置设为仓库
    2. 在剩余客户中选择最近的
    3. 检查容量和时间约束
    4. 移动到选定客户
    5. 重复直到无法继续

  改进策略:
    - 多重启动: 从不同客户开始
    - 时间导向: 考虑时间窗紧迫性
    - 容量导向: 考虑剩余容量匹配

扫描算法 (Sweep Algorithm):
  基本思想:
    - 以仓库为中心进行角度扫描
    - 按角度顺序将客户分组
    - 每组内部优化路径

  算法步骤: 1. 计算所有客户相对仓库的极角
    2. 按极角排序客户
    3. 按车辆容量将客户分组
    4. 每组内解决TSP问题

  适用场景:
    - 客户地理分布相对集中
    - 容量约束为主要限制
    - 需要快速分组的场景
```

### 改进启发式算法

```yaml
2-opt改进:
  基本操作:
    - 删除路径中两条边
    - 重新连接形成新路径
    - 检查是否改进解质量

  实现要点:
    route: [0, 1, 2, 3, 4, 0]
    删除边: (1,2) 和 (3,4)
    新路径: [0, 1, 3, 2, 4, 0]

  适用性:
    - 路径内优化
    - 距离最小化目标
    - 快速局部改进

Or-opt改进:
  基本操作:
    - 选择连续的k个客户
    - 将其重新插入路径其他位置
    - 检查约束可行性和改进效果

  变种:
    - 1-opt: 移动单个客户
    - 2-opt: 移动两个连续客户
    - 3-opt: 移动三个连续客户

路径间交换:
  客户交换:
    - 两条路径间交换客户
    - 保持约束可行性
    - 改进总体目标

  路径段交换:
    - 交换两条路径的子段
    - 考虑容量和时间约束
    - 可能同时改进两条路径

  链交换:
    - 复杂的多客户交换
    - 涉及多条路径
    - 计算复杂但效果好

变邻域搜索 (VNS):
  邻域结构:
    N1: 客户重新插入
    N2: 客户交换
    N3: 路径段交换
    N4: 路径合并分割

  搜索策略: 1. 随机选择邻域结构
    2. 在选定邻域中搜索
    3. 如果找到改进解则重新开始
    4. 否则转到下一邻域结构
```

### 元启发式算法适配

```yaml
遗传算法适配:
  编码方式:
    整数编码: [3,1,4,2,5,0,7,6,8]
    0为分隔符，表示两条路径

  交叉算子:
    顺序交叉 (OX): 保持客户访问顺序
    部分匹配交叉 (PMX): 保持位置关系

  变异算子:
    客户交换: 随机交换两个客户位置
    路径内2-opt: 路径内边交换
    客户重分配: 客户在路径间移动

  适应度评估:
    主目标: 总距离/成本
    约束惩罚: 容量和时间窗违反

模拟退火适配:
  初始解生成:
    - 使用构造启发式获得初始解
    - 或随机生成可行解

  邻域操作:
    - 客户重新插入
    - 2-opt/3-opt改进
    - 路径间客户交换

  接受准则:
    P(accept) = exp(-ΔE/T)
    其中ΔE为解的恶化量，T为温度

蚁群算法适配:
  信息素矩阵:
    τ(i,j): 从客户i到客户j的信息素

  启发信息:
    η(i,j) = 1/d(i,j): 距离倒数

  状态转移概率:
    p(i,j) = [τ(i,j)]^α × [η(i,j)]^β / Σ分母

  信息素更新:
    τ(i,j) = (1-ρ)τ(i,j) + Σ(Δτ)
    其中ρ为挥发系数
```

## 📊 领域特定指标

### 运营效率指标

```yaml
车辆利用率:
  载重利用率 = 实际载重 / 额定载重
  体积利用率 = 实际体积 / 额定体积
  综合利用率 = min(载重利用率, 体积利用率)

  目标值:
    优秀: >85%
    良好: 70-85%
    一般: 50-70%
    较差: <50%

时间利用率:
  工作时间利用率 = 有效工作时间 / 总工作时间
  有效工作时间 = 行驶时间 + 服务时间
  无效时间 = 等待时间 + 空驶时间

里程效率:
  空驶率 = 空驶里程 / 总里程
  配送密度 = 配送件数 / 行驶里程
  路径效率 = 实际里程 / 理论最短里程

客户服务指标:
  准时率 = 准时到达客户数 / 总客户数
  客户满意度 = 满意客户数 / 总客户数
  投诉率 = 投诉次数 / 配送次数
```

### 成本效益指标

```yaml
配送成本: 单件配送成本 = 总配送成本 / 配送件数
  单公里成本 = 总成本 / 总里程
  单客户成本 = 总成本 / 服务客户数

成本构成: 固定成本占比 = 固定成本 / 总成本
  变动成本占比 = 变动成本 / 总成本
  人工成本占比 = 人工成本 / 总成本

盈利能力: 毛利率 = (收入 - 变动成本) / 收入
  净利率 = (收入 - 总成本) / 收入
  投资回报率 = 净利润 / 投资总额

比较基准:
  vs 竞争对手: 成本和服务水平对比
  vs 历史数据: 改进程度评估
  vs 理论最优: 优化潜力分析
```

### 环境影响指标

```yaml
燃料消耗: 百公里油耗 = 总油耗 / 总里程 × 100
  载重油耗 = 总油耗 / (总里程 × 平均载重)
  空驶油耗 = 空驶油耗 / 空驶里程

碳排放: CO2排放量 = 燃料消耗 × 排放因子
  单位排放 = CO2排放量 / 配送件数
  排放强度 = CO2排放量 / 营业收入

环保指标: 电动车比例 = 电动车数 / 总车数
  清洁能源比例 = 清洁能源消耗 / 总能耗
  噪音水平 = 车辆噪音测量值
```

### 求解策略

```yaml
问题规模适配:
  小规模 (<50客户):
    推荐算法: 精确算法、简单启发式
    求解时间: <1分钟
    解质量: 最优或近最优

  中等规模 (50-200客户):
    推荐算法: 元启发式、混合算法
    求解时间: 1-10分钟
    解质量: 95%以上最优

  大规模 (>200客户):
    推荐算法: 分治策略、并行算法
    求解时间: 10-60分钟
    解质量: 90%以上最优

约束复杂度适配:
  简单约束 (仅容量):
    算法选择: 节约算法、2-opt改进
    重点关注: 路径优化

  中等约束 (容量+时间窗):
    算法选择: 启发式+局部搜索
    重点关注: 可行性保证

  复杂约束 (多种约束):
    算法选择: 元启发式+约束处理
    重点关注: 约束满足和目标平衡

实时性要求适配:
  离线优化:
    时间充裕: 追求最优解
    多算法比较: 选择最佳结果

  在线优化:
    时间限制: 快速可行解
    启发式优先: 保证响应时间

  实时调整:
    增量优化: 局部调整策略

```
