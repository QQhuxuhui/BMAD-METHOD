## 🤖 智能体体系架构

### 1. 智能体分层设计

APS 模块采用 **三层智能体架构**：

#### 第一层：编排层

- **系统编排协调智能体 (Orchestrator)**
  - 负责整体流程控制
  - 决策专家调用时机和顺序
  - 管理 Human-in-the-Loop 触发
  - 协调冲突解决

#### 第二层：专家层

- **技术专家组** (4个)
  - 算法专家 (张效率)
  - 约束专家 (李严谨)
  - 目标专家 (王目标)
  - 领域专家 (赵领域)

#### 第三层：支撑层

- **工具专家组** (2个)
  - 算法扩展指导 (钱扩展)
  - 质量评测专家 (孙质量)

### 2. 智能体协作模式

#### 模式A：并行协作（集中确认）

```
Phase 2: 专家协调 (并行模式)

系统编排者
    │
    ├─→ 算法专家 ┐
    ├─→ 约束专家 ├─→ 并行分析 (10-15分钟)
    ├─→ 目标专家 │
    └─→ 领域专家 ┘
         │
         ▼
    一致性校验
         │
         ▼
    (如有冲突) → 冲突仲裁 (P2触发)
```

#### 模式B：串行协作（增量确认）

```
Phase 2: 专家协调 (串行模式)

系统编排者
    │
    ├─→ Phase 2.1: 领域专家 → 用户确认 (P0)
    │        │
    ├─→ Phase 2.2: 约束专家 → 用户确认 (P0)
    │        │
    ├─→ Phase 2.3: 目标专家 → 用户确认 (P0)
    │        │
    ├─→ Phase 2.4: 算法专家 → 用户确认 (P0)
    │        │
    └─→ Phase 2.5: 一致性校验
```

**对比**：

- 模式A：快速高效，适合专家用户，10-15分钟
- 模式B：上下文丰富，适合业务用户，31-48分钟

## 📚 专家知识库架构

### 1. Sidecar 模式设计原理

#### 传统嵌入式 vs Sidecar 模式

**传统嵌入式**（问题）:

```
算法专家.md (50K tokens)
├── 角色定义 (1K)
├── 能力矩阵 (2K)
├── 算法知识 (25K)  ← 每次都加载，但可能只用10%
├── 约束知识 (15K)
└── 示例代码 (7K)
```

- ❌ Token浪费严重
- ❌ 难以维护更新
- ❌ 知识重复冗余

**Sidecar 模式**（解决方案）:

```
算法专家.md (500 tokens)
└── <critical-actions>
    └── 加载 COMPLETE 文件 templates/algorithm-library/README.md

algorithm-library/
├── README.md (5K)      ← 只加载总览
├── exact/              ← 按需加载特定分类
├── heuristic/
└── meta-heuristic/
```

- ✅ Token节省 75-87%
- ✅ 模块化易维护
- ✅ 按需动态加载

### 3. 状态保存与加载流程

#### 保存流程

```
Step X: 保存Phase状态
  │
  ├─→ 1. 收集状态数据
  │      - 从当前执行上下文提取
  │      - 组织成标准化格式
  │
  ├─→ 2. 生成文件名
  │      - {phase_id}_state_{timestamp}.yaml
  │
  ├─→ 3. 写入文件
  │      - 保存到 aps-outputs/states/
  │      - 包含元数据（时间戳、版本等）
  │
  ├─→ 4. 创建 latest 链接
  │      - {phase_id}_state_latest.yaml
  │
  ├─→ 5. 立即验证
  │      - 读取刚保存的文件
  │      - 验证数据完整性
  │      - 验证必需字段存在
  │
  └─→ 6. 返回结果
         - saved_state_file (路径)
         - verification_result (验证结果)
```

#### 加载流程

```
Step X: 加载Phase状态
  │
  ├─→ 1. 前置检查
  │      - 检查文件是否存在
  │      - 缺失则阻断并报错
  │
  ├─→ 2. 加载文件
  │      - 优先使用 latest 链接
  │      - 或指定时间戳版本
  │
  ├─→ 3. 验证数据
  │      - 验证 YAML 格式
  │      - 验证必需字段
  │      - 验证数据类型
  │
  └─→ 4. 返回状态
         - state_data (状态对象)
         - metadata (元数据)
```

### 4. 断点恢复机制

用户可以通过以下命令恢复中断的任务：

```bash
# 检查当前状态
*check-status
  → 显示: 当前Phase、已完成步骤、待执行步骤

# 智能恢复
*resume
  → 自动检测断点位置
  → 加载相关状态文件
  → 从断点处继续执行

# 显示进度
*show-progress
  → 显示: Todo List进度、Phase状态、交付物清单
```

    ├─→ [Phase 2] 目标专家 → objective_analysis

## 🔐 安全与约束架构

### Guardrails 约束机制

#### 知识来源白名单

```yaml
allowed_sources:
  - TenElementModel
  - @专家库/*
  - @知识模块库/*
```

#### 强制引用策略

- 每个推荐、建议、决策必须附@引用路径
- 无引用 = 无效输出
- 自动检测未引用内容并拒绝

#### 能力缺口处理

```
检测到知识缺口
    ↓
生成"能力缺口报告"
    ↓
    ├─→ 缺失的知识类型
    ├─→ 已搜索的路径
    └─→ 建议的解决方案
           ↓
    阻断执行 OR 升级裁决
```
