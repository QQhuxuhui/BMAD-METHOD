## 🎯 核心能力框架

### 1. 需求理解与分析能力

**能力描述**: 将业务需求转换为专家协作需求

**分析维度**:

```yaml
需求解析:
  - 业务语言 → 专业语言转换
  - 调度场景识别
  - 隐性需求发现
  - 需求优先级排序

复杂度识别:
  - Level 1(简单): 单一目标+基础约束+小规模
  - Level 2(中等): 多目标+中等约束+中规模
  - Level 3(复杂): 多目标+复杂约束+大规模
  - Level 4(极复杂): 冲突目标+动态约束+超大规模

专家需求匹配:
  - 单领域问题 → 领域专家+技术专家
  - 跨领域问题 → 多领域专家+全技术专家
  - 创新型问题 → 全专家团队+创新思维
  - 优化型问题 → 目标专家主导+其他支撑
```

### 模式推荐逻辑

```python
def recommend_mode(user_profile: dict) -> str:
    """基于用户画像推荐模式"""

    score_centralized = 0
    score_incremental = 0

    # 因素1: 用户经验
    if user_profile.get("has_scheduling_experience", False):
        score_centralized += 3
    else:
        score_incremental += 3

    # 因素2: 时间压力
    if user_profile.get("time_pressure") == "high":
        score_centralized += 2
    elif user_profile.get("time_pressure") == "low":
        score_incremental += 2

    # 因素3: 问题复杂度
    complexity = user_profile.get("problem_complexity", "medium")
    if complexity in ["simple", "medium"]:
        score_centralized += 1
    else:
        score_incremental += 2

    # 因素4: 是否首次使用
    if user_profile.get("first_time_user", True):
        score_incremental += 3
    else:
        score_centralized += 1

    if score_centralized > score_incremental:
        return "centralized"
    else:
        return "incremental"
```

## 🤝 人机交互协议

### 交互触发规则

编排器在以下情况下会触发人机交互,优先级从高到低:

**P0 (最高优先级): Todo List 强制要求**

```yaml
条件: task.metadata.user_confirmation_needed == true
行动: 无条件触发交互
示例场景: 十要素建模、领域识别、约束确认、目标权重
```

**P1: 置信度过低**

```yaml
条件: confidence < 0.70
行动: 触发交互并说明不确定项
示例场景: 需求模糊、多种可能方案、缺少关键信息
```

**P2: 专家建议冲突**

```yaml
条件: 检测到多专家建议矛盾
行动: 呈现冲突分析,请用户裁决
示例场景: 算法选择冲突、约束与目标矛盾
```

**P3: 能力缺口**

```yaml
条件: 专家库中无匹配模块
行动: 输出能力缺口报告,请用户选择策略
示例场景: 特殊领域、罕见约束组合、创新性需求
```

**P4: 用户主动暂停**

```yaml
条件: 用户输入暂停命令
行动: 保存当前状态,等待用户指令
示例场景: 用户需要思考、咨询他人、准备补充信息
```

### 交互实现机制

```python
from tools.interaction.confirmation_trigger import ConfirmationTrigger

trigger = ConfirmationTrigger(confidence_threshold=0.70)

# 步骤1: 检查是否需要触发交互
should_trigger, reason, trigger_type = trigger.should_trigger_interaction(
    task, expert_output, confidence
)

# 步骤2: 如果需要,生成确认提示
if should_trigger:
    prompt = trigger.generate_confirmation_prompt(
        task, expert_name, analysis, trigger_type, uncertainties
    )

    # 步骤3: 显示给用户并等待反馈
    user_input = input(prompt)

    # 步骤4: 解析用户反馈
    decision = trigger.parse_user_response(
        user_input, expected_format, uncertainties
    )

    # 步骤5: 更新模型
    updated_model = trigger.update_model(model, decision)
```

## 📊 Todo List 追踪机制

### 任务状态管理

```python
from tools.planning.todo_tracker import TodoTracker

tracker = TodoTracker(todos)

# 开始任务时
result = tracker.start_task(task_id)
if not result["success"]:
    print(f"⚠️ 依赖未满足: {result['message']}")
    # 等待依赖任务完成

# 执行任务中: 检查偏离
deviation = tracker.check_deviation(task_id, actual_action)
if deviation["is_deviation"]:
    if deviation["severity"] == "high":
        # 严重偏离,暂停并与用户确认
        print(f"🚨 检测到严重偏离:")
        print(f"  预期: {deviation['expected']}")
        print(f"  实际: {deviation['actual']}")
        print(f"  建议: {deviation['recommendation']}")
        # 请用户确认是否继续
    elif deviation["severity"] == "medium":
        # 中度偏离,记录警告
        print(f"⚠️ 检测到中度偏离,已记录")
    # low 偏离不影响执行

# 完成任务后
result = tracker.complete_task(task_id, actual_time="12min")
```

### 偏离检测与纠正

**偏离检测算法**:

```yaml
相似度计算: difflib.SequenceMatcher
偏离阈值: 0.60 (相似度 < 0.60 视为偏离)

严重度分级:
  - High: similarity < 0.30 (严重偏离,需用户确认)
  - Medium: 0.30 ≤ similarity < 0.50 (中度偏离,记录警告)
  - Low: 0.50 ≤ similarity < 0.60 (轻微偏离,允许继续)
```

**纠正建议**:

```python
if deviation["is_deviation"]:
    recommendation = deviation["recommendation"]
    # recommendation 包含:
    # - 偏离原因分析
    # - 建议调整的 Todo 项
    # - 是否需要重新规划
```
