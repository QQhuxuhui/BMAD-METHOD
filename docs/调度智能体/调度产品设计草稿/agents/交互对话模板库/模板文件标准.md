## 📋 模板分类

```yaml
需求澄清模板: requirement_clarification
  - 用于需求分析阶段
  - 触发: 需求描述模糊或不完整
  - 专家: 系统编排协调智能体

领域确认模板: domain_confirmation
  - 用于领域场景识别
  - 触发: 领域分类置信度 < 0.70
  - 专家: 领域应用专家智能体

约束确认模板: constraint_confirmation
  - 用于约束建模和冲突处理
  - 触发: 约束类型或参数不明确
  - 专家: 约束模式专家智能体

目标权重模板: objective_weight
  - 用于多目标优化
  - 触发: 目标权重未指定或冲突
  - 专家: 目标优化专家智能体

算法选择模板: algorithm_selection
  - 用于算法推荐
  - 触发: 多种算法适用需用户选择
  - 专家: 调度算法专家智能体

冲突仲裁模板: conflict_resolution
  - 用于专家建议冲突时
  - 触发: 检测到 P2 专家冲突
  - 专家: 系统编排协调智能体

能力缺口模板: capability_gap
  - 用于专家库无法满足需求时
  - 触发: 检测到 P3 能力缺口
  - 专家: 任意专家
```

## 📐 模板文件结构

每个模板文件必须包含以下部分:

### 1. YAML 元数据头部

```yaml
---
template_type: '模板类型'
expert: '负责专家智能体名称'
trigger_condition: '触发条件描述'
confidence_threshold: 0.70
version: '1.0'
---
```

### 2. 触发场景说明

```markdown
## 触发场景

描述什么情况下使用此模板
```

### 3. 对话结构

```markdown
## 对话结构

### 步骤1: 呈现分析结果

{AI呈现已确定的部分}

### 步骤2: 提出不确定项

{AI列出需要用户确认的问题，提供选项}

### 步骤3: 解析用户反馈

{如何解析用户的自然语言反馈}

### 步骤4: 更新模型

{如何将用户反馈更新到 TenElementModel 或专家输出}
```

### 4. 模板示例

````markdown
## 模板示例

\```yaml
AI: |
{标准化提示模板}

User: {用户反馈示例}

AI: |
{确认和更新反馈}
\```
````

### 5. 相关引用

```markdown
## 相关引用

- @TenElementModel: {相关要素}
- @专家库: {相关模块}
```

## ✅ 模板审核清单

创建新模板时，请确保:

- [ ] YAML 元数据完整且格式正确
- [ ] 触发场景描述清晰明确
- [ ] 对话结构包含所有4个步骤
- [ ] 至少有2个完整的示例对话
- [ ] 标注了相关的 TenElementModel 要素
- [ ] 标注了相关的专家库模块引用
- [ ] 提供了用户反馈解析逻辑
- [ ] 提供了模型更新逻辑
- [ ] 语言友好、易于理解
- [ ] 符合BMAD-METHOD人机协作原则

## 📚 模板使用指南

### 智能体调用

```python
from tools.interaction.confirmation_trigger import ConfirmationTrigger

trigger = ConfirmationTrigger()

# 生成确认提示
prompt = trigger.generate_confirmation_prompt(
    task,
    expert_name,
    analysis,
    reason,
    uncertainties
)

# 解析用户反馈
decision = trigger.parse_user_response(
    user_input,
    expected_format,
    uncertainties
)

# 更新模型
updated_model = trigger.update_model(model, decision)
```

### 模板引用

在智能体文档中引用模板:

```markdown
当置信度 < 0.70 时，触发人机交互:

- 调用模板: @交互对话模板库/约束确认模板.md
- 呈现不确定项给用户
- 解析用户反馈并更新约束模型
```

## 🔄 模板版本管理

```yaml
版本号规则:
  - 主版本号: 重大结构变更
  - 次版本号: 功能增强或重要修复
  - 修订号: 文本修改或小修复

更新记录:
  - 在元数据中记录 updated 字段
  - 在文件末尾添加版本历史章节
```
