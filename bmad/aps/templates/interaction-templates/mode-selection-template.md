# 交互模板: 交互模式选择

**模板ID**: `mode-selection`
**触发级别**: P0 (强制)
**使用场景**: Phase 0.5 - 用户选择集中确认或增量确认模式
**预计时间**: 2-3分钟

## 模板目标

- 清晰说明两种模式的区别
- 帮助用户选择最适合的模式
- 配置后续workflow的执行路径

## 交互流程

### 步骤1: 呈现模式对比

```markdown
## 🎯 选择您的交互模式

在正式开始调度问题求解前，请选择适合您的交互模式：

### 📊 模式对比

| 维度           | 模式A：集中确认        | 模式B：增量确认        |
| -------------- | ---------------------- | ---------------------- |
| **适合人群**   | 专家用户、熟悉调度优化 | 业务用户、需要详细引导 |
| **确认时机**   | 关键决策点集中确认     | 每个专家结果逐步确认   |
| **交互频率**   | 较少（3-4次）          | 较多（8-10次）         |
| **预计时间**   | ⏱️ **70-95分钟**       | ⏱️ **95-130分钟**      |
| **决策自由度** | 高（一次性全局决策）   | 中（渐进式局部决策）   |
| **学习曲线**   | 需要理解整体架构       | 逐步引导，易于理解     |

---

### 模式A: 集中确认模式 ⚡

**特点**: 快速、高效、适合有经验的用户

**工作流程**:
```

Phase 0 → Phase 0.5 → Phase 1 →
Phase 1.5 (一次性确认完整TenElementModel) →
Phase 2 (所有专家并行分析，一次性查看所有结果) →
Phase 3 → Phase 4

```

**关键确认点** (3-4次):
1. ✅ Phase 0: 确认Todo List
2. ✅ Phase 1.5: 确认完整十要素模型（一次性）
3. ✅ Phase 2: 查看所有专家分析，处理冲突（如有）
4. ✅ Phase 4: 确认最终交付

**优势**:
- ⚡ 时间最短（70-95分钟）
- 🔄 专家并行处理，效率高
- 🎯 适合明确知道自己需求的用户

**挑战**:
- 需要一次性理解和决策完整模型
- 需要对调度优化有一定了解

---

### 模式B: 增量确认模式 🎓

**特点**: 渐进、详细、适合需要引导的用户

**工作流程**:
```

Phase 0 → Phase 0.5 → Phase 1 →
Phase 1.5 (仅确认框架，细节后续确认) →
Phase 2.1 (领域专家 → 确认) →
Phase 2.2 (约束专家 → 确认) →
Phase 2.3 (目标专家 → 确认) →
Phase 2.4 (算法专家 → 确认) →
Phase 2.5 (一致性校验) →
Phase 3 → Phase 4

```

**关键确认点** (8-10次):
1. ✅ Phase 0: 确认Todo List
2. ✅ Phase 1.5: 确认十要素框架（类型、数量、名称）
3. ✅ Phase 2.1: 确认领域识别结果
4. ✅ Phase 2.2: 确认约束建模
5. ✅ Phase 2.3: 确认目标和权重
6. ✅ Phase 2.4: 确认算法选择
7. ✅ Phase 2.5: 查看一致性校验
8. ✅ Phase 4: 确认最终交付

**优势**:
- 🎓 每步都有详细解释和引导
- 📚 逐步学习调度优化知识
- 🔍 每个决策点都有充分时间思考

**挑战**:
- ⏱️ 时间较长（95-130分钟）
- 🔄 需要更多轮次交互

---

## 💡 如何选择？

**选择模式A，如果您**:
- ✅ 熟悉调度优化和运筹学
- ✅ 清楚知道自己的需求和约束
- ✅ 希望快速获得结果
- ✅ 能够一次性评估完整的模型

**选择模式B，如果您**:
- ✅ 对调度优化不太熟悉
- ✅ 希望在过程中学习和理解
- ✅ 需要详细的解释和引导
- ✅ 希望在每个决策点都有充分思考时间
- ✅ 问题较复杂，需要分步确认

**不确定？建议选择模式B** - 更稳健，适合大多数场景
```

### 步骤2: 询问用户选择

```markdown
## ❓ 请选择您的模式

**请回复以下之一**:

1. **"选择模式A"** 或 **"A"** - 集中确认模式（70-95分钟）
2. **"选择模式B"** 或 **"B"** - 增量确认模式（95-130分钟）
3. **"我需要更多信息"** - 详细了解某个模式
4. **"推荐"** - 让系统根据您的问题推荐模式

---

💬 **提示**: 如果不确定，建议选择模式B，它更适合大多数用户。
```

### 步骤3: 处理用户选择

**场景A: 用户选择模式A**

```markdown
## ✅ 模式A已选定：集中确认

您已选择**集中确认模式**，这是一个高效的专家级工作流。

**接下来的流程**:

1️⃣ **Phase 1** (10-15分钟): 深入需求分析

- 我会详细理解您的调度问题
- 如遇模糊需求会向您澄清

2️⃣ **Phase 1.5** (10-15分钟): 一次性构建完整TenElementModel

- 包含所有10个要素的详细定义
- 您需要一次性确认整个模型
- ⚠️ 这是关键决策点，请仔细审查

3️⃣ **Phase 2** (10-15分钟): 并行专家分析

- 4位专家同时分析问题
- 您会一次性看到所有专家的建议
- 如有冲突会请您仲裁

4️⃣ **Phase 3-4** (24-32分钟): 集成和质量保证

**工作流已配置为模式A** ✓

准备好了吗？回复"继续"开始Phase 1需求分析。
```

**场景B: 用户选择模式B**

```markdown
## ✅ 模式B已选定：增量确认

您已选择**增量确认模式**，这是一个渐进式的引导工作流。

**接下来的流程**:

1️⃣ **Phase 1** (10-15分钟): 深入需求分析

- 我会详细理解您的调度问题
- 如遇模糊需求会向您澄清

2️⃣ **Phase 1.5** (5-8分钟): 确认十要素框架

- 只确认框架（类型、数量、名称）
- 详细内容将在Phase 2各专家环节逐步确认
- ✅ 快速简单的确认

3️⃣ **Phase 2** (31-48分钟): 逐步专家分析

- Phase 2.1: 领域专家 → 您确认
- Phase 2.2: 约束专家 → 您确认
- Phase 2.3: 目标专家 → 您确认
- Phase 2.4: 算法专家 → 您确认
- Phase 2.5: 一致性校验

4️⃣ **Phase 3-4** (24-32分钟): 集成和质量保证

**工作流已配置为模式B** ✓

准备好了吗？回复"继续"开始Phase 1需求分析。
```

**场景C: 用户请求更多信息**

```markdown
## 📚 详细说明

请问您想了解哪个模式的更多细节？

- 输入 **"模式A详情"** - 查看模式A的详细执行步骤
- 输入 **"模式B详情"** - 查看模式B的详细执行步骤
- 输入 **"对比案例"** - 查看两种模式在实际问题中的应用对比

或者直接告诉我您的疑问，我会详细解答。
```

**场景D: 用户请求推荐**

```markdown
## 🤖 智能推荐

让我根据您的问题特征进行推荐：

**问题分析**:

- 问题复杂度: [评估结果]
- 用户熟悉度: [基于交流判断]
- 时间敏感性: [基于用户需求]

**推荐**: **模式[A/B]**

**推荐理由**:
[具体说明为什么推荐这个模式]

**是否接受推荐?**

- 输入 **"接受"** - 使用推荐模式
- 输入 **"选择[A/B]"** - 选择另一个模式
```

**双模式交互系统**是V4.3的核心创新：

- **模式A**: 适合专家用户，集中确认，70-95分钟
- **模式B**: 适合业务用户，增量确认，95-130分钟
- **灵活配置**: 根据用户选择动态调整workflow
- **用户友好**: 明确对比，帮助用户做出最佳选择
