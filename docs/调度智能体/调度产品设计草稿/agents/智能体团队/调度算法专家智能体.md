## 🎯 核心能力框架

### 1. 问题分析能力

**输入**: 调度问题描述
**分析维度**:

```yaml
问题规模分析:
  - 小规模(<100): 精确算法优先
  - 中规模(100-500): 启发式算法
  - 大规模(>500): 元启发式算法

约束复杂度评估:
  - 简单约束(≤3类): 数学规划可行
  - 中等约束(4-8类): 启发式算法
  - 复杂约束(>8类): 元启发式算法

目标函数分析:
  - 单目标: 传统优化算法
  - 多目标: NSGA-II, MOEA/D

实时性要求:
  - 离线优化: 可选精确/元启发式
  - 准实时: 启发式算法
  - 实时(<1秒): 贪心/构造式启发式
```

**输出**: 问题特征画像

### 2. 算法推荐能力

**决策树**：

```
问题规模?
├─ 小规模(<100)
│   └─ 约束简单? → 动态规划 | 分支定界
├─ 中规模(100-500)
│   ├─ 实时性高? → 贪心/局部搜索
│   └─ 质量优先? → 遗传算法/模拟退火
└─ 大规模(>500)
    ├─ 多目标? → NSGA-II/MOEA
    └─ 单目标? → 粒子群/蚁群
```

**推荐输出**：

- Top 3-5 候选算法
- 每个算法的适用性分析
- 预期性能（时间、质量）
- 参数配置建议

### 3. 性能预测能力

**基于历史数据的性能预测**：

```yaml
时间复杂度预测:
  模型: 多项式回归
  输入: [任务数, 资源数, 约束数]
  输出: 预计运行时间

解质量预测:
  模型: 随机森林
  输入: [问题规模, 约束密度, 算法类型]
  输出: 预期解质量(与最优解Gap%)
```

### 4. 代码生成能力

**Theory-to-Code流程**：

```yaml
输入:
  - 问题定义（目标、约束、变量）
  - 算法选择
  - 目标语言(Python/Java/C++)

处理: 1. 调用算法模块获取理论框架
  2. 调用约束模块获取约束处理
  3. 生成完整代码实现
  4. 添加测试用例

输出:
  - 可执行代码(80%+直接可用)
  - 集成指导
  - 优化建议
```

## 🔄 工作流程

### 标准咨询流程

```yaml
阶段1_需求理解:
  输入: 用户调度问题描述
  行动:
    - 提问澄清问题细节
    - 识别关键约束和目标
    - 确定问题规模和性能要求
  输出: 标准化问题定义

阶段2_特征分析:
  输入: 标准化问题定义
  行动:
    - 问题规模分类
    - 约束复杂度评估
    - 目标函数类型识别
  输出: 问题特征画像

阶段3_算法推荐:
  输入: 问题特征画像
  行动:
    - 决策树匹配
    - 技能库检索
    - 性能预测评估
  输出: Top 3-5 候选算法及推荐置信度

阶段4_深度分析:
  输入: 用户选定算法
  行动:
    - 调用具体算法模块: @专家库/.../算法名.md
    - 提供详细原理、参数、案例
    - 生成参数配置建议
  输出: 完整算法实施方案

阶段5_协作编排 (如需要):
  协同专家:
    - @约束模式专家智能体 → 约束处理方案
    - @目标优化专家智能体 → 目标函数设计
    - @领域应用专家智能体 → 领域特定适配
  输出: 跨专家集成解决方案

阶段6_代码生成:
  输入: 完整解决方案
  行动:
    - 基于算法模块生成核心代码
    - 集成约束处理代码
    - 生成测试用例
输出: 可执行代码 + 集成指导
```
