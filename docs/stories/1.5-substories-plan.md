# Story 1.5 子Story拆分计划

## 概述

Story 1.5（迁移八大智能体到LangGraph 1.0）规模较大，包含19个任务。按照BMAD最佳实践，拆分为4个子Story，分阶段实施。

## 子Story划分

### Story 1.5.1: 核心智能体节点实现

**优先级**: 高 (P0)
**依赖**: 无（基础架构已在Story 1.5中完成）
**预估工作量**: 2-3天

#### 包含任务

- ✅ Task 1: 设计LangGraph StateGraph架构（已完成）
- ⏳ Task 2: 实现Orchestrator智能体节点（部分完成）
- Task 3: 实现Algorithm Expert智能体节点
- Task 4: 实现Constraint Expert智能体节点
- Task 5: 实现Objective Expert智能体节点
- Task 6: 实现Domain Expert智能体节点
- Task 7: 实现Code Implementation Expert智能体节点
- Task 8: 实现Extension Expert智能体节点
- Task 9: 实现Quality Expert智能体节点
- ✅ Task 15: 集成Model Adapter Service（已完成）

#### 验收标准

1. 8个智能体节点全部实现
2. 每个节点有对应的Prompt模板（markdown格式）
3. 每个节点有单元测试（使用mock）
4. 所有节点能正确解析LLM JSON输出
5. 集成测试：单独调用每个节点成功

#### 交付物

- 8个agent节点Python文件（`agents/*.py`）
- 8个Prompt模板文件（`prompts/*.md`）
- 8个单元测试文件（`tests/unit/test_*_agent.py`）
- 更新README文档

### Story 1.5.2: StateGraph编排和Checkpoint持久化

**优先级**: 高 (P0)
**依赖**: Story 1.5.1（需要所有agent节点实现完成）
**预估工作量**: 1-2天

#### 包含任务

- Task 10: 实现StateGraph编排器
- Task 11: 配置PostgreSQL Checkpoint持久化
- Task 14: 工作流配置兼容性适配（支持YAML配置）

#### 验收标准

1. StateGraph成功编译，包含所有8个agent节点
2. 条件边路由逻辑正确（Phase 0-4流转）
3. PostgreSQL Checkpoint自动保存和恢复
4. 支持从YAML加载智能体配置
5. 集成测试：完整工作流执行（不含HITL）

#### 交付物

- `workflow.py` - StateGraph定义和编译
- `config_loader.py` - YAML配置加载器
- Checkpoint数据库迁移脚本
- 集成测试文件
- 配置迁移指南文档

---

### Story 1.5.3: API端点和数据库Schema

**优先级**: 中 (P1)
**依赖**: Story 1.5.2（需要工作流可运行）
**预估工作量**: 2-3天

#### 包含任务

- Task 12: 实现HITL中断和恢复机制
- Task 13: 实现工作流执行API端点
- Task 16: 实现数据模型和数据库Schema

#### 验收标准

1. 数据模型：WorkflowExecution, AgentExecution, HumanApproval
2. Alembic数据库迁移成功
3. API端点：
   - POST /api/v1/workflows（创建工作流）
   - GET /api/v1/workflows/{id}（获取状态）
   - GET /api/v1/workflows/{id}/stream（SSE流式输出）
   - POST /api/v1/workflows/{id}/resume（恢复工作流）
   - DELETE /api/v1/workflows/{id}（取消工作流）
4. HITL中断点（P1, P2, P2.5）正确触发
5. 工作流恢复后状态一致

#### 交付物

- 3个SQLModel数据模型文件
- Alembic迁移脚本
- `api/v1/workflows.py` - API路由
- `services/workflow_service.py` - 业务逻辑
- HITL实现文件
- API文档（OpenAPI schema）

## 风险和缓解

| 风险                    | 缓解策略                    |
| ----------------------- | --------------------------- |
| LLM输出格式不一致       | 使用Pydantic严格校验        |
| Checkpoint保存失败      | PostgreSQL事务+重试机制     |
| 性能不达标              | 分阶段优化，Story 1.5.4专项 |
| Agent节点实现耗时超预期 | 创建通用Agent基类减少重复   |
