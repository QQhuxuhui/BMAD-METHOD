系统组成
系统由五类核心智能体及共享资源构成，并通过 LangGraph 定义确定性、有状态的有向图流程：

1. 路由智能体
   功能：路由智能体接受用户自然语言提问，进行意图识别、领域分类、问题类型判定；根据问题拆解任务，选择和编排后续能力节点。查询专家库以获取可复用模板、优先算法或约束条件。
   实现方式：
   使用大模型做自然语言理解与规划：短上下文提示模板包含问题、领域标签、受限能力列表、要求的输出格式。
   能力匹配算法：语义检索（向量检索）结合规则匹配（正则/关键词）对候选能力打分，选最优能力输出。

2. 机器学习算法智能体
   功能：判断并调用适当的已有机器学习/物理模型（例如焊接缺陷检测模型、热传导仿真、工艺参数响应曲面模型等）。
   若无适配模型，返回“无法用现有算法直接解答”的标识，由路由智能体转发到数据库探查智能体。
   实现方式：
   维护模型元数据：专家库文档描述已有的各个机器算法的接口地址、功能描述、参数内容等信息，根据模型大类进行归类（如机床丝杆类、机床主轴类、机床刀具类等）
   根据用户问题，首先调用大模型根据专家库匹配模型大类，然后将该类别下各模型的详细描述加入提示词，调用大模型返回匹配的接口地址信息。
   根据接口信息包含的数据需求查询专家库，匹配所需数据的数据库地址，将相关信息结合接口信息，查询并返回计算结果。

3. 数据库探查智能体
   功能：将用户问题或 Router 分解后的数据需求转为结构化查询（SQL），并返回若干样例数据或数据摘要。
   实现方式：
   智能体首先获取数据库表结构、字段类型、关系等元信息，构建schema的向量表示，便于语义匹配，缓存常用表和字段的描述信息。
   使用LLM理解用户意图（查询、统计、筛选等），识别关键实体（表名、字段名、条件值），解析时间、数值等特殊表达。
   基于schema信息和用户意图生成初始SQL，SQL语法检查智能体验证生成的查询，性能优化智能体建议索引使用、查询重写。
   安全执行SQL查询。
   具体流程如图二所示：
   步骤一：数据库连接引擎的初始化构建
   接收用户输入的数据库配置信息，所述配置信息包括数据库主机地址、端口号、数据库名称、访问用户名、密码以及数据库类型标识。根据所述数据库类型标识，动态选择对应的数据库驱动程序：当数据库类型为MySQL时，采用PyMySQL驱动；当数据库类型为PostgreSQL时，采用Psycopg2驱动。基于所选驱动构造标准化的数据库连接统一资源标识符，并通过LangChain框架提供的数据库封装接口，创建一个可复用的数据库连接实例对象。若输入的数据库类型不在支持列表中，则触发类型不支持异常；所有异常信息均被捕获并记录至全局状态对象中的错误消息字段，供后续节点判断流程终止条件。
   步骤二：可用数据表的枚举与登记
   在成功建立数据库连接的基础上，调用数据库连接实例提供的元数据访问接口，获取当前数据库中所有可访问的数据表名称列表。将该列表保存至全局状态对象的“可用表列表”字段中，同时将数据库连接的脱敏后地址信息记录至“连接地址”字段，用于操作溯源与审计。若在获取表名过程中发生访问异常或权限不足等情况，系统将捕获异常信息，并将其写入状态对象的错误消息字段，后续处理节点检测到错误消息后将提前退出执行流程。
   步骤三：相关数据表的语义筛选
   基于用户提出的自然语言问题，结合步骤二中获取的可用表列表，进行语义层面的相关性判断。系统构造包含可用表清单及用户问题的提示文本，交由预设的大语言模型进行分析处理。大语言模型根据上下文理解，输出与问题最相关的若干表名，以逗号分隔的形式返回。系统对返回结果进行解析，并与可用表列表进行交集运算，以过滤掉不存在或不可访问的表名，确保结果的有效性。若模型返回“无相关表”或解析后无有效匹配，则将“相关表列表”字段置为空列表。若此过程中出现模型调用失败或其他异常，同样记录至状态对象的错误消息字段；若可用表列表本身为空，则本步骤直接跳过，不进行进一步处理。
   步骤四：目标表结构的元数据提取
   针对步骤三中确定的相关数据表列表，逐一对各表进行结构信息提取。利用SQLAlchemy提供的元数据检查功能，访问数据库底层引擎，获取每张表的列名、数据类型、是否允许空值等列级属性信息。将这些元数据规范化为统一格式的描述字符串，格式为：“列名（数据类型）[NOT NULL]”，其中“NOT NULL”仅在该列不允许为空时添加。所有列信息按表名组织为字典结构，存储于全局状态对象的“表结构信息”字段中。若相关表列表为空，则本步骤提前结束；若在读取元数据过程中发生异常，则记录错误信息并终止后续执行。
   步骤五：安全合规的只读查询语句生成
   综合用户问题、已获取的表结构信息及用户额外提供的业务语义说明，生成符合安全规范的只读数据查询语句。系统首先将各相关表的列结构汇总为结构化文本描述，构造给大语言模型的提示内容，并明确约束生成要求：仅允许生成SELECT类型的查询语句，禁止任何数据写入、修改、删除或数据库结构变更操作；建议在查询中加入结果数量限制（LIMIT）以防止大数据量返回；应使用标准SQL语法，并合理使用连接（JOIN）操作关联多表数据。
   模型返回的原始响应需经过后处理：去除代码块标记符（如```sql）等非SQL内容。随后，系统启动三层安全校验机制，对生成的SQL语句进行合法性审查：
   语句类型校验：验证语句去除首尾空白后是否以“SELECT”开头（不区分大小写），否则判定为非法；
   危险关键字过滤：检测语句中是否包含预设的危险操作关键字，如INSERT、UPDATE、DELETE、DROP、ALTER、EXECUTE等，一旦发现即视为不安全；
   多语句注入防范：检查语句中是否包含分号（;）字符，若除语句末尾外存在其他分号，则认为可能存在多语句注入风险，判定为不安全。
   只有通过上述三项校验的SQL语句，才被认定为安全合规，保存至状态对象的“生成SQL”字段。若任一校验未通过，或在生成过程中发生异常，则将相应的错误原因写入状态对象的错误消息字段，流程终止，不再向下执行。
4. 数据分析智能体
   功能：在获得问题、SQL 及样例数据后，自动生成 Python 分析脚本（含数据加载、清洗、特征工程、统计检验、可视化），执行并循环自修复（基于异常堆栈与单元化断言）直到得到稳定产物或达到安全边界。
   产物：中间数据表、图表（时序趋势、箱线图、Pareto、热力图、工艺窗口图）、统计结论（如 t 检验/方差分析/相关性/SHAP 解释）。
   具体步骤如图3所示
   步骤一：数据分析代码的智能生成
   接收用户输入的自然语言查询，结合上下文环境，调用大语言模型生成对应的Python数据分析代码。生成过程中，系统通过构造结构化提示词，明确要求所生成代码必须满足以下条件：
   包含必要的库导入语句；
   实现对数据的加载、清洗、转换与分析逻辑；
   将最终分析结果封装为名为 execution_result 的字典变量，并通过 print(execution_result) 输出，以便后续提取。
   若用户上下文涉及数据库操作（SQL由上一个节点的数据探查智能体得来），系统将自动构造SQLAlchemy格式的数据库连接字符串，并在提示词中引导模型生成包含数据查询与本地分析的完整代码流程。生成的代码文本保存至状态对象的“生成代码”字段。
   步骤二：代码的安全执行与结果捕获
   将步骤一中生成的Python代码在隔离的执行环境中运行。系统采用python自带的 exec 函数，在一个独立的局部变量字典环境中执行代码，避免对全局命名空间造成污染，提升执行安全性。
   执行完成后，系统检查该局部环境中是否存在名为 execution_result 的变量。若存在，则将其内容提取并序列化为标准数据结构，存入状态对象的“执行结果”字段，并将“执行状态”置为“成功”；若执行过程中发生语法错误、运行时异常或依赖缺失等问题，则捕获异常类型与堆栈信息，记录至“错误信息”字段，并将“执行状态”置为“失败”。
   步骤三：执行结果的判定与流程分支控制
   对上一步的执行状态进行判断，决定后续处理路径：
   若“执行状态”为“成功”，则跳转至最终处理节点；
   若“执行状态”为“失败”，则进一步检查“重试次数”字段：
   若重试次数小于预设阈值（默认为3次），则进入代码修复流程；
   若重试次数已达上限，则不再尝试修复，直接进入最终处理节点，返回错误总结。
   该判断机制防止无限循环，保障系统在持续失败情况下仍能终止并反馈。
   步骤四：错误代码的智能修复
   针对执行失败的代码，系统启动修复机制。利用大语言模型，结合原始生成代码、错误信息及上下文查询内容，重新生成修正后的Python代码。提示词中明确提供：
   原始代码内容；
   具体错误类型与位置描述；
   修复建议（如补全导入、修正语法、处理空值等）。
   模型输出为完整的、可替代原代码的新版本，覆盖所有修复内容。修复后的代码重新写入“生成代码”字段，重试次数加1，并循环返回至步骤二进行重新执行，形成“生成→执行→修复”的反馈闭环。
   步骤五：最终结果的整合与输出
   当流程因成功执行或达到最大重试次数而终止时，进入最终处理阶段：
   若“执行状态”为“成功”，则将“执行结果”字段中的数据结构化内容作为最终输出，以JSON格式返回；
   若流程因多次失败终止，则系统汇总历次错误信息，生成简明的错误原因总结，作为最终结果返回，帮助用户理解失败原因。
   最终结果统一写入状态对象的“最终结果”字段，并通过接口返回给调用方。

5. 报告智能体（Report Agent）
   功能：依据分析或模型结果、专家规则，调用大语言模型，生成固定格式的结构化报告（摘要、数据来源、方法、结果、结论与建议、风险与限制、附录 SQL/参数/版本号）。

（2）本发明的关键点（详细说明本发明的改进点，并描述各改进点所要解决的技术问题是什么，对应优点）：
本发明的关键在于提出一种基于LangGraph的多智能体协同架构，将大模型的自然语言理解与规划能力作为核心驱动，结合领域专家库、机器学习模型及数据库查询，实现从用户提问到分析报告的全流程自动化。
其创新点在于通过路由智能体对用户问题进行解析和任务分解，智能选择后续能力节点；通过机器学习算法智能体调用已注册的领域模型完成计算；通过数据库探查智能体生成并校验安全的查询语句以获取所需数据；再由数据分析智能体自动合成并执行分析代码，遇到错误可进行迭代修复；最终由报告智能体生成可追溯、带有证据链的分析报告。
该体系结构的关键技术是利用LangGraph将各智能体以图结构进行编排，确保数据流与任务流的可控与可追溯，并通过专家库和安全控制机制保证分析结果的准确性、合规性和可复现性，从而实现焊接领域复杂问题的智能化、自动化解决方案。
（3）本发明的技术效果（由本发明的改进所直接决定的有益效果或优点）
本发明通过将LangGraph图结构编排、多智能体协同与大模型能力深度结合，带来一系列明显且可量化的技术效果。
首先，显著提升了问题响应的自动化与效率：自然语言输入由路由智能体自动解析、拆解并分配任务，后续各能力节点按图路径并行或串行执行，减少人工干预，整体响应时间与人工处理成本大幅降低。
其次，提高了诊断与分析结论的准确性与一致性：机器学习算法智能体调用已验证的模型，数据库探查与数据分析智能体在受控沙箱中执行，报告智能体基于同一证据链生成结论，避免了传统流程中因人工拼接信息带来的主观偏差。
第三，增强了可追溯性与可复现性：系统对每次请求保留完整的 task-plan、SQL、执行脚本、模型版本及执行日志，任何结论均可回溯到具体的模型、代码与数据样本，满足质量管理与审计需求。
第四，提升了系统鲁棒性与安全合规能力：对LLM生成的SQL/代码实施静态校验与沙箱预执行，实行权限控制与脱敏策略，最大限度降低数据泄露、越权访问与不可控命令执行风险。
第五，改善了维护性与扩展性：能力节点采用插件化注册与专家库管理，新模型、新数据源或新模板可通过在专家库中登记并在LangGraph中新增节点快速上线，降低系统演化成本。
第六，支持人与机器协同的可控降级：当自动流程置信度不足或修复循环失败时，系统自动触发人工介入工单并附带完整调试包，实现平滑的人工接管与知识回写。
第七，带来决策支持价值与产业应用潜力：通过标准化的分析产出与结构化报告，管理层和现场工程师能够更快采纳优化建议，从而提升焊接品质、降低返修率并优化工艺参数。
第八，促进持续学习与知识沉淀：专家库与模型目录的版本化与审计机制，使得人工专家的判定、模型更新和修复经验得以沉淀并反馈至系统，形成闭环改进。
综上，本发明在效率、准确性、安全性、可维护性与产业适配性等方面均有显著技术提升，能够为焊接领域提供一种高效、可靠且可审计的智能分析与报告生成解决方案。
