# 四、专家知识库体系

## 4.1 知识库架构

采用 **Sidecar 模式** 实现知识的模块化组织和按需加载：

| 知识库                   | 对应专家     | 分类体系                                                    | 模块数量 | Token节省 |
| ------------------------ | ------------ | ----------------------------------------------------------- | -------- | --------- |
| **orchestrator-library** | 系统编排协调 | collaboration/decision/integration/risk                     | -        | -         |
| **algorithm-library**    | 调度算法专家 | exact/heuristic/meta-heuristic                              | 13+      | **87%**   |
| **constraint-library**   | 约束模式专家 | capacity/temporal/spatial/logical/business-rules            | 20+      | **60%**   |
| **objective-library**    | 目标优化专家 | cost/time/quality/efficiency/sustainability/multi-objective | 15+      | **67%**   |
| **domain-library**       | 领域应用专家 | vehicle/production/project/service/supply-chain             | 10+      | **56%**   |
| **quality-library**      | 质量评测专家 | syntax/logic/consistency/benchmark/report                   | 8+       | -         |
| **modeling-library**     | 通用建模     | core/ten-element/time-model/uncertainty                     | 5+       | -         |

## 4.2 知识引用规范

```yaml
标准引用格式:
  @专家库/<library>/<category>/<module>.md

示例:
  - @专家库/算法库/meta-heuristic/遗传算法.md
  - @专家库/约束库/temporal/时间窗约束.md
  - @专家库/目标库/cost/成本最小化.md
  - @专家库/领域库/vehicle/车辆路径领域.md

引用验证:
  - Phase 4 质量门禁强制检查所有引用
  - 引用缺失 → 质量门禁失败 → 阻断交付
```

# 五、产品功能清单

## 5.1 核心功能

### 1. 完整调度求解 (\*start-scheduling)

```
输入: 自然语言业务需求
输出:
  - 调度解决方案文档 (YAML)
  - 可执行Python代码
  - 质量验证报告
  - 所有交付物文件

流程: Phase 0 → 0.5 → 1 → 1.5 → 2 → 3 → 4
时间: 70-130分钟
```

### 2. 智能断点恢复 (\*resume)

```
场景: 工作流中断（网络/错误/用户退出）
能力:
  - 检查当前执行状态
  - 验证状态文件完整性
  - 从断点处智能继续
  - 保留所有上下文

命令:
  *check-status  # 查看当前状态
  *resume        # 智能恢复
  *show-progress # 显示Todo进度
```

### 3. 方案优化 (\*optimize-solution)

```
场景: 已有初步方案，需要优化调整
输入: 自然语言优化需求
  "我想增加一个约束，确保同一设备不能同时处理多个任务"
  "遗传算法跑得太慢了，能不能优化一下参数"
  "准时交货的重要性应该更高一些"

能力:
  - 自动理解优化需求
  - 调用合适的专家（约束/算法/目标）
  - 生成优化方案
  - 保持原方案一致性
```

### 4. 独立代码生成 (\*generate-code)

```
场景: 已有方案YAML，需要生成代码实现
输入: 方案YAML文件
输出:
  - 完整Python实现
  - 测试用例
  - 运行说明
  - 依赖配置

Theory-to-Code能力:
  - 代码可用率 92%+
  - 自动生成测试
  - 完整注释文档
```

### 5. 十要素建模 (\*build-model)

```
场景: 单独执行建模流程
输出: TenElementModel (统一真相源)
  1. 决策变量定义
  2. 参数配置
  3. 约束模型
  4. 优化目标
  5. 算法选择
  6. 时间模型
  7. 不确定性处理
  8. 求解配置
  9. 输入数据格式
  10. 输出结果格式

应用:
  - 需求标准化
  - 方案沟通
  - 跨专家协作的统一语言
```

## 5.3 质量保证功能

```yaml
质量门禁 (Phase 4):
  1. 语法检查
     - Python代码语法正确性
     - YAML格式验证
     - 缩进与编码检查

  2. 逻辑验证
     - 约束逻辑一致性
     - 目标函数正确性
     - 算法流程完整性

  3. 约束一致性检查
     - TenElementModel与代码一致
     - 跨专家建议无冲突
     - 参数配置合理性

  4. 引用完整性 (Guardrails)
     - 所有模块附@引用路径
     - 引用路径有效性验证
     - 能力缺口报告检查

  5. 基准测试
     - 简单数据集运行
     - 性能指标评估
     - 与预期对比

  6. 交付物完整性
     - 所有文件已保存到磁盘
     - 文件路径正确
     - 文件内容完整

门禁结果:
  level: pass  → 允许交付
  level: warn  → 警告但可交付
  level: fail  → 阻断交付
```

# 六、技术创新点

## 6.1 "Agent as Doc" 理念

**业界首创**：将智能体定位为知识文档的动态加载器和组合器

```
传统LLM Agent痛点:
  ✗ Prompt工程混乱，难以维护
  ✗ 知识嵌入prompt，Token浪费
  ✗ 专家经验难以结构化
  ✗ 知识更新需重写prompt

APS创新解决:
  ✓ 智能体 = 轻量角色 + 知识文档库
  ✓ 知识以Markdown模板形式组织
  ✓ 动态加载按需组合
  ✓ 知识更新只需更新模板文件
  ✓ 多智能体可复用同一知识库

价值:
  • Token效率提升 75-87%
  • 知识维护效率提升 10倍
  • 专家经验可标准化传承
  • 支持知识的持续积累和演进
```

## 6.2 模块化知识库架构

**Sidecar 模式**：按需加载，精准匹配

**对比传统方式**：

```
传统: Agent加载全部知识 50K → 实际使用 5K → 浪费 45K (90%)
Sidecar: Agent 0.5K + README 5K + 按需模块 3.5K = 9K (节省 82%)
```

## 6.3 Theory-to-Code 自动化

**从理论到代码的完整链路**：

```
输入: 业务需求 (自然语言)
  ↓
Phase 1: 需求理解 → 结构化需求
  ↓
Phase 1.5: 十要素建模 → TenElementModel (统一真相源)
  ↓
Phase 2: 专家协调 → 算法/约束/目标/领域方案
  ↓
Phase 3: 方案集成 → 完整YAML方案
  ↓
Theory-to-Code引擎:
  • 调用算法模板 (@专家库/算法库/*)
  • 插入约束逻辑 (@专家库/约束库/*)
  • 嵌入目标函数 (@专家库/目标库/*)
  • 添加领域适配 (@专家库/领域库/*)
  • 生成测试用例
  • 生成运行说明
  ↓
输出: 可执行Python代码 (92%可用率)

创新点:
  ✓ 自动化率 85%+
  ✓ 代码质量高 (基于验证模板)
  ✓ 完整注释和文档
  ✓ 开箱即用
```

## 6.4 状态持久化 + 智能续传

**业界首创调度Agent的断点续传能力**：

```yaml
创新点: • 每个Phase强制保存状态到文件系统
  • 保存后立即验证完整性
  • 状态文件包含所有上下文
  • 智能恢复算法检测断点位置
  • 自动加载依赖状态
  • 继续执行无需重新输入

应用场景: ✓ 网络中断后恢复
  ✓ 用户主动暂停后继续
  ✓ 错误修复后重试
  ✓ 分多次完成长流程
  ✓ 团队协作交接
```

## 6.5 Todo List + 偏离检测

**将需求管理引入Agent工作流**：

```
创新机制:
  1. Phase 0生成Todo List (基于需求理解)
  2. 用户确认 → 形成"执行合同"
  3. 实时追踪每个Todo执行状态
  4. 语义相似度检测偏离 (threshold=0.60)
  5. 偏离触发警告 + 人工介入
  6. Phase 4验证所有Todo完成

价值:
  • 任务偏离率降低 67%
  • 需求遗漏率降低 80%
  • 用户参与感提升
  • 执行过程可追溯

对比传统Agent:
  传统: 需求理解 → 黑盒执行 → 输出结果
        (用户无法追踪过程，容易偏离需求)

  APS: 需求理解 → Todo确认 → 实时追踪 → 偏离检测 → 最终验证
       (全程可见可控)
```
