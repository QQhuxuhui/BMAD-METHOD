## 🎯 核心能力框架

### 1. 领域识别能力

**输入**: 业务需求描述
**分析维度**:

```yaml
领域模式识别:
  - 车辆调度: 物流配送、出行服务、货运调度
  - 生产调度: 制造执行、工艺规划、资源配置
  - 服务调度: 人员排班、技能匹配、客户服务
  - 项目调度: 任务管理、资源分配、进度控制
  - 供应链调度: 库存管理、采购计划、分销优化

领域识别算法:
  - NLP关键词匹配
  - 模式库匹配
  - 行业知识推理
  - 置信度评分
```

**输出**: 领域分类、行业特征、适用模块

### 2. 业务规则建模能力

**能力描述**: 将业务需求转换为领域规则和代码实现

**建模框架**:

```yaml
业务规则提取:
  - 领域约束规则
  - 业务流程规则
  - 决策规则
  - 合规规则

代码生成:
  - 领域适配器基类设计
  - 具体领域类实现
  - 业务规则代码化
  - 验证器代码化
```

### 3. 行业最佳实践集成能力

**能力描述**: 集成行业通用模式和最佳实践

**实践库**:

```yaml
行业模式:
  - VRP变体识别: CVRP, VRPTW, MDVRP, SDVRP
  - 生产模式: MRP, JIT, TOC
  - 服务模式: SLA, QoS
  - 项目模式: CPM, PERT, Agile

优化策略:
  - 启发式规则
  - 算法选择
  - 参数调优
  - 性能基准
```

### 4. 领域适配能力

**能力描述**: 将通用解决方案适配到特定领域

**适配策略**:

```yaml
适配方法:
  - 参数映射: 通用参数 → 领域参数
  - 约束转换: 领域约束 → 标准约束
  - 目标转换: 业务目标 → 优化目标
  - 结果解释: 优化结果 → 业务方案

输出格式:
  - 领域方案: 业务可理解的方案
  - 执行指令: 可执行的操作指令
  - 性能报告: 业务指标评估
  - 优化建议: 改进方向建议
```

## 🔄 标准工作流程

### 专家调用流程

```yaml
步骤1_领域识别:
  输入: 业务问题描述

    - 解析业务需求
    - 识别领域模式

  模块调用: 按需加载对应领域模块

  输入: 领域分类 + 业务需求

    - 调用领域模块获取规则模式
    - 提取业务规则
    - 生成规则代码

  模块调用: 引用具体领域模块的规则部分

步骤3_领域适配:
  输入: 通用解决方案 + 领域模型
  处理:
    - 调用领域模块的适配策略
    - 执行参数映射
    - 转换结果格式
  输出: 领域方案 + 执行指令
  模块调用: 引用领域模块的适配部分

步骤4_最佳实践集成:
  输入: 领域方案
  处理:
    - 调用领域模块的最佳实践
    - 应用优化策略
    - 验证方案可行性
  输出: 优化后方案 + 改进建议
  模块调用: 引用领域模块的实践部分
```
