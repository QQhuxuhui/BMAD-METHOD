## 🎯 方案概述

### 版本定位

**版本号**: V4.2
**代号**: "Human-in-the-Loop + Todo Planning" - 人机协同规划增强
**核心升级**: 从"自动化执行"到"可控协同执行"的架构演进

V4.2 是在 V4.1 "模块化架构" 基础上的重大工作流升级，引入两大核心机制：

1. **📋 Todo List 任务规划机制** - 防止任务链幻觉和偏离
2. **🤝 Human-in-the-Loop 人机交互机制** - 关键决策点用户确认

### 设计动机

#### 当前问题 (V4.1)

```yaml
问题1_任务链幻觉:
  现象: 智能体在长任务链中可能偏离原始目标
  原因: 缺乏明确的"执行合同"和检查点
  影响: 用户发现问题时已经执行了大量无效工作
  严重度: ⭐⭐⭐⭐☆ (高)

问题2_黑盒执行:
  现象: 用户只能在最终结果时才能介入
  原因: 智能体自主决策，缺乏关键节点确认
  影响: 需求理解偏差导致大量返工
  严重度: ⭐⭐⭐⭐☆ (高)

问题3_低置信度猜测:
  现象: 专家在不确定时仍会"猜测"并继续
  原因: 缺乏置信度阈值和主动询问机制
  影响: 基于错误假设的后续工作全部作废
  严重度: ⭐⭐⭐⭐⭐ (极高)
```

#### 业界最佳实践借鉴

```yaml
UltraThink (Claude Code):
  核心理念: Analysis → Planning → Execution → Review
  关键价值: 明确的规划阶段，深度思考预算
  借鉴点: Phase 0 规划阶段，生成 Todo List

Sequential Thinking Ultra (MCP):
  核心理念: 逐步处理 + 质量验证 + 元推理检查点
  关键价值: 每一步都有质量验证，偏差检测
  借鉴点: Checkpoint 机制，置信度追踪

BMAD-METHOD:
  核心理念: Human-in-the-Loop，人机协作而非 AI 独断
  关键价值: 迭代设计，用户全程参与
  借鉴点: 关键决策点的用户确认机制
```

## 📐 架构设计

### V4.2 工作流升级

#### 完整工作流对比

| 阶段 | V4.1 工作流 | V4.2 工作流                    | 变化    |
| ---- | ----------- | ------------------------------ | ------- |
| 0    | ❌ 无       | ✅ **Phase 0: 任务规划**       | 🆕 新增 |
| 1    | 需求分析    | 需求分析 + **Todo 检查**       | 🔧 增强 |
| 1.5  | 十要素建模  | 十要素建模 + **用户确认**      | 🔧 增强 |
| 2    | 专家协调    | 专家协调 + **Todo 追踪**       | 🔧 增强 |
| 3    | 知识组装    | 知识组装 + **交互确认**        | 🔧 增强 |
| 4    | 方案集成    | 方案集成 + **冲突仲裁**        | 🔧 增强 |
| 5    | 质量保证    | 质量保证 + **Todo 完成度检查** | 🔧 增强 |

#### V4.2 标准工作流

```yaml
Phase_0_任务规划与Todo生成 (🆕新增):
  输入: 用户需求
  主导: @系统编排协调智能体

  步骤1_需求初步解析:
    - 识别核心任务和子任务
    - 评估复杂度和预估时间
    - 识别关键依赖关系
    - 调用: @专家库/系统编排专家库/决策策略/复杂度评估策略.md

  步骤2_生成Todo List:
    工具: python tools/planning/todo_generator.py
    结构:
      - content: 任务描述 (祈使句)
      - activeForm: 执行时的进行时态
      - status: pending|in_progress|completed
      - metadata:
          priority: 1-5 (优先级)
          estimated_time: 预估时间
          dependencies: 依赖的前置任务ID列表
          expert: 负责专家
          checkpoint: 是否为关键检查点
          confidence: 0.0-1.0 (置信度)
          user_confirmation_needed: 是否需要用户确认
          gate: 是否为质量门禁

  步骤3_Todo List用户确认:
    - 呈现给用户审阅 (格式化显示)
    - 用户可修改优先级、添加/删除任务
    - 用户确认后锁定 (成为"执行合同")
    - 生成任务依赖关系图 (可选)

  输出:
    - 经用户确认的 Todo List
    - 任务依赖关系图 (Mermaid格式)
    - 预估总时间和关键路径

  工具调用:
    - TodoWrite (Claude Code 内置工具)
    - tools/planning/todo_generator.py (自定义生成器)

Phase_1_需求分析:
  输入: 用户需求 + Todo List
  约束: 必须参考 Todo List 中的任务范围
  新增: 每次子任务完成后更新 Todo 状态
  工具: tools/planning/todo_tracker.py (追踪执行状态)

Phase_1.5_十要素建模:
  输入: 需求模型 + Todo List
  Todo状态: pending → in_progress
  新增:
    - 生成 TenElementModel 后，标记 user_confirmation_needed=true
    - 触发人机交互，逐要素确认不确定项
    - 用户确认后，Todo状态: in_progress → completed
  置信度阈值: < 0.70 自动触发交互
  工具: tools/interaction/confirmation_trigger.py

Phase_2_专家协调:
  输入: TenElementModel + Todo List
  新增:
    - 每个专家任务开始前，检查 Todo List 依赖
    - 每个专家任务完成后，更新 Todo 状态
    - 如果检测到偏离，触发告警并请求用户裁决
  工具: tools/planning/todo_tracker.py (偏离检测)

Phase_3_知识组装:
  输入: 专家协作计划 + Todo List
  新增:
    - 每个专家输出前，检查 user_confirmation_needed 标志
    - 如果需要确认，使用交互对话模板呈现给用户
    - 用户确认后，专家继续执行
  置信度阈值: < 0.70 自动触发交互
  对话模板: docs/agents/交互对话模板库/*.md

Phase_4_方案集成:
  输入: 各专家建议 + TenElementModel + Todo List
  新增:
    - 检测专家建议冲突时，自动触发用户仲裁
    - 呈现冲突分析和建议，由用户做最终决策
  工具: tools/interaction/conflict_resolver.py

Phase_5_质量保证:
  输入: 集成方案 + Todo List
  新增检查项:
    - ✅ 所有 Todo 任务是否已完成
    - ✅ 实际执行是否偏离 Todo List
    - ✅ 偏离原因记录与合理性评估
    - ✅ 用户确认次数和有效性分析
  工具:
    - python tools/validation/aggregator.py (QE门禁)
    - tools/planning/todo_tracker.py (完成度分析)
```

#### 交互触发规则

```yaml
触发规则优先级:
  P0_Todo List强制要求:
    条件: task.metadata.user_confirmation_needed == true
    行动: 无条件触发，呈现标准化提示
    示例: 十要素建模、领域识别、约束定义、目标权重

  P1_置信度过低:
    条件: confidence < 0.70
    行动: 触发并说明不确定项
    示例: '我识别到这可能是VRPTW问题 (置信度0.65)，但...'

  P2_专家建议冲突:
    条件: 检测到多专家建议矛盾
    行动: 呈现冲突分析，请用户裁决
    示例: 算法专家推荐GA vs 约束专家建议TS

  P3_能力缺口:
    条件: 专家库中无匹配模块
    行动: 输出"能力缺口报告"，请用户选择降级或扩展
    示例: "我无法找到'多仓库多车型'的约束模板..."

  P4_用户主动暂停:
    条件: 用户输入 "pause" 或 "等一下"
    行动: 暂停执行，等待用户指令
```

## ⚠️ 风险与应对

### 风险清单

```yaml
R1_用户交互频率过高:
  风险: 用户需要频繁确认，体验下降
  概率: 中等
  影响: 中等
  应对:
    - 智能调整置信度阈值 (自适应学习)
    - 批量确认机制 (一次呈现多个确认项)
    - 用户可设置"专家模式" (减少确认)

R2_时间估算不准:
  风险: Todo List 时间估算偏差大，用户期望管理失败
  概率: 高
  影响: 低
  应对:
    - 标注估算置信度 (如 "5-8分钟")
    - 基于历史数据持续优化估算模型
    - 明确告知用户"仅供参考"

R3_偏离检测误报:
  风险: 正常的任务执行被误判为偏离
  概率: 中等
  影响: 中等
  应对:
    - 采用语义相似度而非严格字符串匹配
    - 设置偏离阈值 (相似度 <0.60 才告警)
    - 用户可手动标记"忽略此偏离"

R4_工具实现复杂度高:
  风险: 工具实现耗时超预期
  概率: 中等
  影响: 高
  应对:
    - 采用迭代开发，先实现 MVP
    - 复杂功能 (如语义相似度) 可延后
    - 优先保证核心流程可用
```

from tools.planning.todo_generator import V4TodoGenerator

generator = V4TodoGenerator()

requirements = {

    "domain": "vehicle_routing",

print(generator.format_for_display(todos))

#### 2. 检测是否需要人机交互

```python
from tools.interaction.confirmation_trigger import ConfirmationTrigger

trigger = ConfirmationTrigger()

task = todos[1]  # 十要素建模任务
expert_output = {
    "ten_element_model": {...},
    "uncertainties": [
        {
            "element": "constraints",
            "description": "时间窗是硬约束还是软约束？",
            "options": ["硬约束", "软约束(允许延迟)"]
        }
    ]
}
confidence = 0.65

should_trigger, reason = trigger.should_trigger_interaction(
    task, expert_output, confidence
)

if should_trigger:
    prompt = trigger.generate_confirmation_prompt(
        task,
        "系统编排协调智能体",
        expert_output,
        reason
    )
    print(prompt)

    # 等待用户反馈
    user_input = input("请确认: ")

    # 解析并更新
    decision = trigger.parse_user_response(user_input, {...})
    updated_model = trigger.update_model(expert_output, decision)
```

#### 3. 追踪执行与偏离检测

```python
from tools.planning.todo_tracker import TodoTracker

tracker = TodoTracker(todos)

# 开始任务
tracker.start_task(task_id=2)

# 执行过程中检测偏离
actual_action = "正在分析约束条件的优先级"
deviation = tracker.check_deviation(task_id=2, actual_action)

if deviation["is_deviation"]:
    print(f"⚠️ 检测到偏离: {deviation['explanation']}")
    print(f"建议: {deviation['recommendation']}")

# 完成任务
tracker.complete_task(task_id=2, actual_time="12min")

# 生成完成报告
report = tracker.generate_completion_report()
print(report)
```
