## 🧬 算法知识本体

### 核心原理

```yaml
生物学隐喻:
  个体: 问题的一个候选解
  种群: 候选解的集合
  基因: 解的组成部分
  染色体: 解的编码表示
  适应度: 解的质量评价

进化过程:
  选择: 根据适应度选择优秀个体
  交叉: 两个个体交换基因片段
  变异: 随机改变个体的某些基因
  替换: 新个体替换旧个体
```

### 算法框架

```yaml
基本步骤: 1. 初始化种群
  2. 评估适应度
  3. 选择操作
  4. 交叉操作
  5. 变异操作
  6. 环境选择
  7. 终止判断

关键参数:
  种群大小: 50-200 (推荐100)
  交叉概率: 0.7-0.9 (推荐0.8)
  变异概率: 0.01-0.1 (推荐0.05)
  最大代数: 100-1000 (根据问题复杂度)
```

## 🎯 应用场景知识

### 适用问题类型

```yaml
调度优化:
  - 车辆路径规划问题 (VRP)
  - 作业车间调度问题 (JSP)
  - 人员排班优化问题
  - 资源分配优化问题

问题特征:
  搜索空间: 大规模、复杂
  约束条件: 多约束、非线性
  目标函数: 单目标或多目标
  解的结构: 离散或连续

优势场景:
  - 传统方法难以求解的NP-hard问题
  - 需要全局搜索的优化问题
  - 多模态优化问题
  - 动态优化问题
```

### 不适用场景

```yaml
限制条件:
  - 简单的线性规划问题 → 使用单纯形法
  - 小规模问题 → 使用精确算法
  - 实时性要求极高 → 使用贪心算法
  - 单调优化问题 → 使用梯度方法
```

  交叉算子:
    - 单点交叉

### 生产调度编码

## ⚙️ 算子设计知识

### 选择算子知识库

```yaml
轮盘赌选择:
  原理: 根据适应度比例随机选择
  特点: 保持种群多样性
  适用: 适应度差异不大的问题

  实现要点:
    - 计算累积概率
    - 随机数映射选择
    - 避免适应度为负数

锦标赛选择:
  原理: 随机选择k个个体进行竞争
  特点: 控制选择压力
  适用: 大多数优化问题

  参数设置:
    - 锦标赛规模: 2-7 (推荐3)
    - 选择压力可调
    - 实现简单高效

精英保留:
  原理: 保留最优个体到下一代
  特点: 保证解质量不退化
  适用: 所有优化问题

  保留比例: 5-20% (推荐10%)
```

### 交叉算子知识库

```yaml
单点交叉:
  适用编码: 二进制、实数
  参数: 交叉点位置
  特点: 简单、快速

多点交叉:
  适用编码: 二进制、实数
  参数: 交叉点数量
  特点: 增加搜索多样性

均匀交叉:
  适用编码: 二进制
  参数: 交叉概率
  特点: 每个位置独立交叉

算术交叉:
  适用编码: 实数
  公式: child = α×parent1 + (1-α)×parent2
  参数: α ∈ [0,1]
  特点: 保持数值范围
```

### 变异算子知识库

```yaml
位翻转变异:
  适用编码: 二进制
  操作: 0→1, 1→0
  概率: 1/L (L为染色体长度)

高斯变异:
  适用编码: 实数
  操作: x' = x + N(0,σ²)
  参数: 标准差σ
  特点: 正态分布扰动

多项式变异:
  适用编码: 实数
  特点: 模拟二进制变异
  参数: 分布指数η

交换变异:
  适用编码: 排列
  操作: 交换两个位置的基因
  特点: 保持排列性质
```

## 📊 参数调优知识

### 种群大小设置

```yaml
小种群 (20-50):
  优点: 计算效率高
  缺点: 容易陷入局部最优
  适用: 简单问题、快速原型

中等种群 (50-200):
  优点: 平衡效率和效果
  缺点: 参数敏感
  适用: 大多数实际问题

大种群 (200-500):
  优点: 搜索能力强
  缺点: 计算成本高
  适用: 复杂问题、高精度要求
```

### 概率参数设置

```yaml
交叉概率调优:
  高交叉率 (0.8-0.95):
    - 加快收敛速度
    - 可能破坏好的解结构
    - 适用于早期搜索阶段

  低交叉率 (0.6-0.8):
    - 保持解的稳定性
    - 收敛速度较慢
    - 适用于后期精细搜索

变异概率调优:
  高变异率 (0.05-0.2):
    - 增加种群多样性
    - 防止早熟收敛
    - 可能破坏收敛进程

  低变异率 (0.01-0.05):
    - 局部精细搜索
    - 维持解的质量
    - 可能陷入局部最优

自适应策略:
  线性递减: Pm(t) = Pm_max - (Pm_max-Pm_min)×t/T
  指数递减: Pm(t) = Pm_max × exp(-t/τ)
  基于适应度: Pm = f(fitness_diversity)
```

## 🎯 性能评估知识

### 收敛性分析

```yaml
收敛曲线:
  横轴: 进化代数
  纵轴: 最优适应度值

  理想模式:
    - 初期快速下降
    - 中期稳定改进
    - 后期缓慢收敛

多样性指标:
  基因型多样性: 不同个体比例
  表型多样性: 适应度方差

  计算公式: D = Σ(fi - f_avg)² / N
    其中fi为个体i的适应度
```

### 算法对比基准

```yaml
与其他算法对比:
  vs 精确算法:
    - 解质量: 95-99%最优解
    - 计算时间: 可接受范围内

  vs 其他启发式:
    - 模拟退火: 收敛稳定性更好
    - 粒子群: 参数设置更灵活
    - 蚁群算法: 适用问题更广泛

性能指标:
  解质量: Best, Average, Worst
  收敛速度: 达到目标解的代数
  稳定性: 多次运行的标准差
  计算时间: CPU时间、函数评价次数
```

## 🛠️ 实现指导知识

### 关键实现要点

```yaml
初始化策略:
  随机初始化: 保证种群多样性
  启发式初始化: 结合问题特征
  混合初始化: 部分随机+部分启发式

终止条件设计:
  最大代数: 防止无限循环
  收敛判断: 连续N代无改进
  目标值: 达到预设质量
  时间限制: CPU时间约束

内存管理:
  种群存储: 考虑内存占用
  历史信息: 保存最优解轨迹
  垃圾回收: 及时释放无用内存
```

### 常见问题解决

```yaml
早熟收敛:
  原因: 选择压力过大、变异率过低
  解决: 增加变异率、多样性保持、重启机制

收敛缓慢:
  原因: 种群规模过小、交叉率过低
  解决: 增大种群、提高交叉率、精英策略

解的质量不稳定:
  原因: 参数设置不当、编码不合理
  解决: 参数调优、改进编码方式

内存消耗过大:
  原因: 种群规模过大、存储冗余
  解决: 动态种群、压缩存储
```
