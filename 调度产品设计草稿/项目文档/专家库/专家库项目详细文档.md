# 智能调度算法专家库 - 项目详细文档

## 📋 项目概述

智能调度算法专家库是一个基于人工智能的调度算法自动生成系统，能够根据用户的自然语言需求描述，自动推荐最适合的调度算法、约束处理方式和优化目标，并生成可直接部署的完整调度系统代码。

### 🎯 项目目标

- **降低技术门槛**: 让非专业用户也能获得高质量的调度算法解决方案
- **提高开发效率**: 将6-12个月的开发周期缩短到2-4周
- **保证算法质量**: 基于调度优化领域专家知识，确保算法选择的专业性和合理性
- **支持快速部署**: 提供从算法到生产环境的完整解决方案

### 🏗️ 技术架构

专家库采用**四库协同架构**：

```
智能调度算法专家库
├── 算法模板库 (Algorithm Templates)
├── 约束模式库 (Constraint Patterns)
├── 目标函数库 (Objective Functions)
├── 领域模板库 (Domain Templates)
└── 核心编排器 (Orchestrator)
```

## 📚 核心组件详细说明

### 1. 核心编排器 (Core Orchestrator)

**文件**: `expert_library/core/orchestrator.py`

**功能**: 系统的核心控制器，负责协调四大组件库的协同工作

**主要方法**:

- `process_user_request()`: 处理用户请求的完整流程
- `identify_domain()`: 领域识别算法
- `recommend_algorithms()`: 算法推荐
- `identify_constraints()`: 约束识别
- `recommend_objectives()`: 目标函数推荐
- `generate_solution_template()`: 生成解决方案模板

**工作流程**:

```
用户需求 → 需求解析 → 领域识别 → 算法推荐 → 约束识别 → 目标确定 → 方案生成
```

### 2. 算法模板库 (Algorithm Templates)

**目录**: `expert_library/algorithms/`

**功能**: 提供多种经典调度算法的模板实现

#### 2.1 贪心分配算法 (`greedy_assignment.py`)

- **适用场景**: 小规模问题，需要快速响应
- **时间复杂度**: O(n×m)
- **特点**: 简单高效，适合实时调度

#### 2.2 匈牙利分配算法 (`hungarian_assignment.py`)

- **适用场景**: 任务与资源一对一匹配
- **时间复杂度**: O(n³)
- **特点**: 保证最优解，适合成本敏感场景

#### 2.3 遗传调度算法 (`genetic_scheduler.py`)

- **适用场景**: 大规模复杂调度问题
- **时间复杂度**: O(generations × population × evaluation)
- **特点**: 启发式搜索，适合多约束多目标优化

### 3. 约束模式库 (Constraint Patterns)

**目录**: `expert_library/constraints/`

**功能**: 提供常见调度约束的标准化处理模式

### 4. 目标函数库 (Objective Functions)

**目录**: `expert_library/objectives/`

**功能**: 提供多种优化目标的标准实现

#### 4.1 最小化总时间 (`minimize_total_time.py`)

```python
def evaluate_objective(schedule_data, domain_context):
    """计算总完成时间"""
    return max(task['finish_time'] for task in schedule_data['tasks'])
```

#### 4.2 最小化总成本 (`minimize_total_cost.py`)

```python
def evaluate_objective(schedule_data, domain_context):
    """计算总运营成本"""
    return sum(resource['cost'] * resource['usage_time']
              for resource in schedule_data['resources'])
```

#### 4.3 最大化利用率 (`maximize_utilization.py`)

```python
def evaluate_objective(schedule_data, domain_context):
    """计算资源利用率"""
    total_capacity = sum(r['capacity'] for r in schedule_data['resources'])
    used_capacity = sum(r['used_capacity'] for r in schedule_data['resources'])
    return used_capacity / total_capacity
```

### 5. 领域模板库 (Domain Templates)

**目录**: `expert_library/domains/`

**功能**: 提供不同应用领域的专门化模板和知识

#### 5.1 车辆调度领域 (`vehicle_scheduling.py`)

- **典型应用**: 物流配送、出租车调度、公交排班
- **关键实体**: 车辆、驾驶员、路线、配送点
- **常见约束**: 车辆容量、行驶距离、工作时间
- **常见目标**: 最小化总距离、最大化车辆利用率

#### 5.2 生产调度领域 (`production_scheduling.py`)

- **典型应用**: 制造业生产计划、车间作业调度
- **关键实体**: 机器、工人、订单、工序
- **常见约束**: 机器容量、工艺顺序、交货期限
- **常见目标**: 最小化完工时间、最大化设备利用率

#### 5.3 服务调度领域 (`service_scheduling.py`)

- **典型应用**: 医院排班、维修服务、客服中心
- **关键实体**: 服务人员、客户、服务请求、时间段
- **常见约束**: 技能匹配、工作时间、服务水平
- **常见目标**: 最大化客户满意度、均衡工作负载

### 6. 智能需求解析器 (Smart Parser)

**文件**: `expert_library/utils/smart_parser.py`

**功能**: 将用户的自然语言需求转换为结构化的调度问题描述

#### 6.1 三层解析架构

- **关键词解析器**: 基于模式匹配的快速解析
- **LLM智能解析器**: 基于大语言模型的语义理解
- **混合解析器**: 结合两者优势，智能选择最佳解析策略

#### 6.2 解析结果结构

```python
@dataclass
class ParsedRequirement:
    description: str                    # 原始描述
    entities: Dict[str, List[str]]     # 识别的实体
    constraints: List[Dict[str, Any]]   # 约束信息（含置信度）
    objectives: List[Dict[str, Any]]    # 目标信息（含置信度）
    domain_hints: List[Dict[str, Any]]  # 领域提示（含置信度）
    complexity: str                     # 问题复杂度
    confidence_score: float             # 整体置信度
    parsing_method: str                 # 解析方法
```

## 🚀 使用方法

## 🆘 故障排除

### 常见问题

#### 1. 算法推荐置信度低

**问题**: 系统返回的算法推荐置信度始终低于期望值

**可能原因**:

- 用户需求描述不够详细
- 领域识别失败
- 相似度计算参数需要调整

**解决方案**:

```python
# 调整匹配阈值
config = {"matching_threshold": 0.5}  # 降低阈值
orchestrator = ExpertLibraryOrchestrator(config=config)

# 使用更详细的需求描述
detailed_request = """
我们是一家物流公司，有30辆不同载重的配送车辆。
每天处理约500个配送订单，分布在城市的5个区域。
每个订单有明确的时间窗口要求（上午9点到下午6点）。
我们希望优化配送路径，主要目标是最小化总的配送时间，
同时考虑车辆的载重限制和燃油成本。
"""
```

#### 2. 生成代码编译错误

**问题**: 生成的Python代码存在语法错误或导入错误

**可能原因**:

- 代码模板存在bug
- 参数注入过程中的字符串处理错误

**解决方案**:

```python
# 验证生成的代码
def validate_generated_code(code_template):
    try:
        compile(code_template, '<string>', 'exec')
        return True
    except SyntaxError as e:
        print(f"代码语法错误: {e}")
        return False

# 在使用前验证
result = orchestrator.process_user_request(user_request)
code = result['solution_template']['code_template']
if validate_generated_code(code):
    print("代码验证通过")
else:
    print("代码需要修正")
```

#### 3. 性能问题

**问题**: 处理大规模请求时响应缓慢

**解决方案**:

```python
# 启用缓存
from functools import lru_cache

# 配置并发处理
import concurrent.futures

def process_requests_concurrently(requests):
    with concurrent.futures.ThreadPoolExecutor(max_workers=4) as executor:
        futures = [executor.submit(orchestrator.process_user_request, req)
                  for req in requests]
        results = [future.result() for future in futures]
    return results
```
