# Agent文档中心 - V4.2 "Theory-to-Code" 智能体团队

## 🆕 V4.2 新增功能 (2025-10-14)

### 📋 Todo List 任务规划机制

防止任务链幻觉和偏离:

- **Phase 0: 任务规划** - 自动生成任务清单作为"执行合同"
- **实时追踪执行状态** - TodoTracker 持续监控任务偏离
- **偏离检测与纠正** - 相似度 < 0.60 时暂停并确认

**核心工具**:

- `tools/planning/todo_generator.py` - 自动生成结构化 Todo List
- `tools/planning/todo_tracker.py` - 任务追踪与偏离检测

### 🤝 Human-in-the-Loop 人机交互机制

关键决策点用户确认:

- **五级触发规则** (P0-P4) - P0: Todo强制 | P1: 置信度<0.70 | P2: 冲突 | P3: 能力缺口 | P4: 用户暂停
- **标准化对话模板** - 7个场景模板 (需求澄清、领域确认、约束确认、目标权重、冲突仲裁、能力缺口)
- **置信度阈值: 0.70** - 低于阈值自动触发用户确认

**核心工具**:

- `tools/interaction/confirmation_trigger.py` - 智能交互触发器

**交互模板库**:

- `docs/agents/交互对话模板库/` - 标准化交互对话模板

## 🎯 设计理念：从技术实现到知识载体

**核心转变**：Agent as Doc - 智能体作为知识文档化载体，而非技术实现系统

- ❌ **技术实现方式**：代码实现、服务器配置、部署指南
- ✅ **知识模板方式**：知识模块、调用接口、模板依赖

## 🚀 V4.0实例化机制

### 五阶段动态知识组装

```yaml
阶段1_需求分析:
  调用: @系统编排协调智能体.需求理解
  知识依赖: [@需求解析模板, @场景识别模板]
  输出: 标准化需求模型

阶段2_专家协调:
  调用: @系统编排协调智能体.专家编排
  知识依赖: [@协作协议模板, @编排策略模板]
  输出: 专家协作计划

阶段3_知识组装:
  调用: @各专家智能体.知识模板
  知识依赖: [@算法模板, @约束模板, @目标模板, @领域模板]
  输出: 定制化解决方案

阶段4_方案集成:
  调用: @系统编排协调智能体.方案整合
  知识依赖: [@集成优化模板, @质量保证模板]
  输出: 完整解决方案

阶段5_质量保证:
  调用: @系统编排协调智能体.质量评估
  知识依赖: [@验证模板, @评估模板]
  输出: 经过验证的最终方案
```


## 💡 核心特征

### Agent as Doc理念体现

- **知识载体**：智能体作为知识的载体和组织者
- **模板调用**：通过@符号进行标准化知识调用
- **依赖管理**：清晰的知识模板依赖关系
- **动态组合**：基于需求的知识模块动态组装

### 产品思想对齐

- **bmad-method风格**：文档依赖调用方式
- **知识模块化**：可组合、可复用、可扩展
- **专家角色定位**：知识载体而非技术实现
- **实用性保证**：完整的使用指南和实例演示
