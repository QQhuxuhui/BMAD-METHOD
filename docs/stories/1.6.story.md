## Dev Notes

### LangServe概述

**LangServe是什么** [Source: LangChain Official Docs]:

- LangChain官方提供的FastAPI部署工具
- 自动将LangChain Runnable转换为RESTful API
- 内置OpenAPI文档、Swagger UI、Playground
- 支持流式输出（SSE）和批量处理
- 版本要求：0.3.0+（当前项目尚未安装）

**核心优势**:

- 减少80%的API开发时间
- 自动生成客户端代码
- 内置请求验证和错误处理
- 无缝集成FastAPI生态（中间件、依赖注入）

### LangServe核心API

**add_routes函数签名** [Source: /langchain-ai/langserve]:

```python
def add_routes(
    app: FastAPI,
    runnable: Runnable,
    *,
    path: str,
    input_type: Type = None,
    output_type: Type = None,
    config_keys: Sequence[str] = (),
    include_callback_events: bool = False,
    enable_feedback_endpoint: bool = False,
    enable_public_trace_link_endpoint: bool = False,
    playground_type: Literal["default", "chat"] = "default",
    dependencies: Sequence[Depends] = None,
    per_req_config_modifier: Callable = None,
) -> None
```

**自动生成的端点** [Source: /langchain-ai/langserve README]:

| 端点             | 方法 | 描述                  | 响应格式                |
| ---------------- | ---- | --------------------- | ----------------------- |
| `/invoke`        | POST | 同步调用runnable      | JSON                    |
| `/batch`         | POST | 批量调用（多个输入）  | JSON                    |
| `/stream`        | POST | 流式输出              | text/event-stream (SSE) |
| `/stream_log`    | POST | 流式输出+中间步骤日志 | text/event-stream (SSE) |
| `/stream_events` | POST | 结构化事件流（推荐）  | text/event-stream (SSE) |
| `/playground/`   | GET  | Web UI测试界面        | HTML                    |

    def __init__(self, workflow_service):
        self.workflow_service = workflow_service

    def invoke(self, input: dict, config: RunnableConfig = None) -> dict:
        """同步执行工作流（阻塞直到完成）"""
        # 1. 从config提取user_id
        # 2. 调用workflow_service.create_workflow()
        # 3. 等待工作流完成
        # 4. 返回output_data
        pass

    async def ainvoke(self, input: dict, config: RunnableConfig = None) -> dict:
        """异步执行工作流"""
        pass

    def stream(self, input: dict, config: RunnableConfig = None) -> Iterator[dict]:
        """流式输出工作流状态（同步生成器）"""
        pass

    async def astream(self, input: dict, config: RunnableConfig = None) -> AsyncIterator[dict]:
        """流式输出工作流状态（异步生成器）"""
        # 1. 创建工作流
        # 2. 使用workflow_service.stream_workflow_events()
        # 3. yield每个event（phase_change, agent_output, approval_required等）
        pass

### JWT认证集成策略

**策略1：使用path dependencies（推荐）** [Source: /langchain-ai/langserve auth examples]:

```python
from app.api.v1.auth import get_current_user

add_routes(
    app,
    bmad_runnable,
    path="/bmad-workflow",
    dependencies=[Depends(get_current_user)],  # 全局依赖
)
```

**优点**:

- 自动集成到OpenAPI文档
- 所有LangServe端点统一认证
- 与现有FastAPI auth无缝集成

**策略2：使用per_req_config_modifier（高级）** [Source: /langchain-ai/langserve]:

```python
async def inject_user_context(
    raw_request: Request,
    config: RunnableConfig,
) -> RunnableConfig:
    """从Request中提取user并注入到config"""
    token = raw_request.headers.get("Authorization", "").replace("Bearer ", "")
    user = await get_user_from_token(token)

    return {
        **config,
        "configurable": {
            **config.get("configurable", {}),
            "user_id": user.id,
        }
    }

add_routes(
    app,
    bmad_runnable,
    path="/bmad-workflow",
    per_req_config_modifier=inject_user_context,
)
```

**优点**:

- 可以在Runnable内部访问user_id
- 支持per-user逻辑（如文档权限控制）

**本Story采用**：策略1（全局依赖）+ 策略2（用户上下文传递）的组合

### 流式输出实现

**SSE Event格式** [Source: /langchain-ai/langserve stream_events]:

```json
event: data
data: {"event": "on_chain_start", "data": {...}}

event: data
data: {"event": "on_llm_stream", "data": {"chunk": "..."}}

event: data
data: {"event": "on_chain_end", "data": {...}}

event: end
```

**BMAD工作流事件映射**:

| BMAD Event         | LangServe Event Type | 说明                     |
| ------------------ | -------------------- | ------------------------ |
| workflow_started   | on_chain_start       | 工作流开始               |
| phase_changed      | on_chain_stream      | Phase转换（P0→P1→P2...） |
| agent_started      | on_tool_start        | 智能体开始执行           |
| agent_output       | on_tool_end          | 智能体完成               |
| approval_required  | on_chain_stream      | HITL中断点               |
| workflow_completed | on_chain_end         | 工作流完成               |

**实现示例**:

```python
async def astream(self, input: dict, config: RunnableConfig = None):
    workflow_id = await self.create_workflow(input, config)

    async for event in self.workflow_service.stream_events(workflow_id):
        yield {
            "event": map_bmad_to_langserve_event(event.type),
            "data": event.data,
        }
```

### 前端集成示例

**Vue 3 Composition API Hook** [Source: Architecture - Frontend Best Practices]:

```typescript
// frontend/web/src/composables/useBMADWorkflow.ts
import { ref } from 'vue';
import { RemoteRunnable } from '@langchain/core/runnables/remote';

export function useBMADWorkflow() {
  const isStreaming = ref(false);
  const output = ref<string>('');
  const error = ref<Error | null>(null);

  const runWorkflow = async (input: WorkflowInput) => {
    const runnable = new RemoteRunnable({
      url: 'http://localhost:8000/api/v1/bmad-workflow',
      options: {
        headers: {
          Authorization: `Bearer ${getToken()}`,
        },
      },
    });

    isStreaming.value = true;
    output.value = '';

    try {
      for await (const chunk of runnable.stream(input)) {
        output.value += JSON.stringify(chunk);
      }
    } catch (e) {
      error.value = e as Error;
    } finally {
      isStreaming.value = false;
    }
  };

  return { runWorkflow, isStreaming, output, error };
}
```

**使用EventSource（原生SSE）**:

```typescript
const eventSource = new EventSource('http://localhost:8000/api/v1/bmad-workflow/stream', {
  headers: {
    Authorization: `Bearer ${token}`,
  },
});

eventSource.onmessage = (event) => {
  const data = JSON.parse(event.data);
  console.log('Received:', data);
};

eventSource.onerror = (error) => {
  console.error('SSE Error:', error);
  eventSource.close();
};
```

### Refactoring Performed

发现并修复了4个关键问题:

#### 1. 🔴 修复 asyncio.run() 在异步上下文中的崩溃问题

**File**: backend/app/core/langgraph/runnable_wrapper.py:176-214

**问题**:

- `invoke()` 方法使用 `asyncio.run()` 会在FastAPI的异步上下文中抛出 `RuntimeError: asyncio.run() cannot be called from a running event loop`
- 这会导致LangServe的/invoke端点在生产环境中完全无法工作

**修复方案**:

```python
# 修复前
def invoke(self, input, config):
    return asyncio.run(self.ainvoke(input, config))  # ❌ 会崩溃

# 修复后
def invoke(self, input, config):
    try:
        loop = asyncio.get_running_loop()
        # 在异步上下文中,使用线程池执行
        with concurrent.futures.ThreadPoolExecutor() as executor:
            future = executor.submit(lambda: asyncio.run(self.ainvoke(input, config)))
            return future.result()
    except RuntimeError:
        # 同步上下文,安全使用asyncio.run()
        return asyncio.run(self.ainvoke(input, config))
```

**Why**: FastAPI在异步环境中运行,LangServe会在已有事件循环中调用invoke(),必须处理这种情况

**Impact**: 🔴 Critical → ✅ Resolved

#### 2. 🔴 修复 stream() 方法的事件循环处理问题

**File**: backend/app/core/langgraph/runnable_wrapper.py:311-385

**问题**:

- 原始实现创建新事件循环,但在FastAPI异步上下文中会冲突
- 可能导致流式端点失败或阻塞

**修复方案**:

- 检测是否在异步上下文中
- 如果是,使用线程池 + queue传递事件
- 如果不是,创建新事件循环

**Why**: 确保stream()在同步和异步上下文中都能正常工作

**Impact**: 🔴 Critical → ✅ Resolved

#### 3. 🟡 优化JWT认证,消除双重认证开销

**File**:

- backend/app/api/v1/langserve_routes.py:18-83
- backend/app/api/v1/auth.py:49-104

**问题**:

- `inject_user_context()` 在 `per_req_config_modifier` 中重新调用 `get_current_user()`
- 导致每个请求JWT认证2次,增加延迟和CPU开销
- 存在时序攻击风险

**修复方案**:

```python
# auth.py: 在get_current_user中存储user到request.state
request.state.user = user

# langserve_routes.py: 从request.state获取user,避免重新认证
user = getattr(request.state, "user", None)
if not user:
    # Fallback: 只在user不存在时才重新认证
    user = await get_current_user(credentials)
```

**Why**:

- 减少认证开销,提升API性能
- 避免重复的数据库查询
- 降低时序攻击风险

**Impact**: 🟡 Performance Issue → ✅ Optimized (预计延迟减少30-50%)

#### 4. ✅ 增强 get_current_user 设置 request.state

**File**: backend/app/api/v1/auth.py:49-104

**Change**: 添加 `request.state.user = user` 以支持下游处理器

**Why**: 使LangServe的config_modifier能够访问已认证的用户,避免重复认证

**How**: 在返回user前,将其存储到request.state中

**Impact**: ✅ Enhancement
