# 交互模板: Todo List确认

**模板ID**: `todo-confirmation`
**触发级别**: P0 (强制)
**使用场景**: Phase 0 - 用户确认Todo List形成执行合同
**预计时间**: 2-3分钟

## 模板目标

- 向用户清晰展示任务清单
- 获取用户确认和调整
- 形成"执行合同"作为偏离检测基线

## 交互流程

### 步骤1: 展示Todo List

```markdown
## 📋 任务规划清单

基于您的需求，我为本次调度问题求解生成了以下任务清单：

### Phase 0: 任务规划 (5-8分钟)

- ✅ 需求理解与初步分析
- ✅ 生成Todo List
- 🔄 **[当前]** 用户确认Todo List
- ⏳ 初始化TodoTracker

### Phase 0.5: 双模式交互选择 (2-3分钟)

- ⏳ 呈现模式对比
- ⏳ 用户选择交互模式
- ⏳ 配置工作流

### Phase 1: 需求分析 (10-15分钟)

- ⏳ 需求深度理解
- ⏳ 用户澄清（如需要）
- ⏳ TodoTracker偏离检测

### Phase 1.5: 十要素建模 (5-15分钟)

- ⏳ 初步建模
- ⏳ 用户确认TenElementModel
- ⏳ 固化TenElementModel

### Phase 2: 专家协调 (10-48分钟，取决于模式)

- ⏳ 领域专家分析
- ⏳ 约束专家分析
- ⏳ 目标专家分析
- ⏳ 算法专家分析
- ⏳ 跨专家一致性校验

### Phase 3: 方案集成 (15-20分钟)

- ⏳ 方案融合
- ⏳ 一致性最终检查
- ⏳ 生成完整代码

### Phase 4: 质量保证 (9-12分钟)

- ⏳ 质量全面验证
- ⏳ 质量门禁判断
- ⏳ Todo完成度检查
- ⏳ 交付确认

---

**⏱️ 预计总时间**:

- 模式A（集中确认）: 70-95分钟
- 模式B（增量确认）: 95-130分钟

**🎯 主要交付物**:

- TenElementModel（十要素模型）
- 完整可执行代码
- 质量验证报告
- Todo完成度报告
```

### 步骤2: 询问用户意见

```markdown
## ❓ 确认与调整

请您确认以下内容：

1. **任务清单是否完整?**
   - 是否覆盖了您的所有需求？
   - 是否有遗漏的重要任务？

2. **优先级是否合理?**
   - 任务顺序是否符合您的期望？
   - 是否需要调整某些任务的优先级？

3. **时间估算是否可接受?**
   - 总时间（70-130分钟）是否在您的预期内？
   - 是否有时间限制需要考虑？

4. **是否需要添加/删除/修改任务?**
   - 请具体说明您的调整需求

**请回复以下之一**:

- ✅ "确认，按此计划执行"
- 📝 "需要调整：[具体调整内容]"
- ❓ "我有疑问：[您的疑问]"
```

### 步骤3: 处理用户反馈

**场景A: 用户直接确认**

```markdown
## ✅ 确认成功

感谢您的确认！此任务清单现在作为我们的"执行合同"，将用于：

1. **进度追踪**: 实时更新每个任务的完成状态
2. **偏离检测**: 如果执行过程偏离计划（相似度<0.60），系统会自动告警
3. **质量保证**: Phase 4会检查所有任务的完成情况

**接下来**: 进入Phase 0.5，选择交互模式（集中确认 vs 增量确认）

---

📊 **TodoTracker已初始化**

- 基线合同: 已固化
- 追踪模式: 实时
- 偏离阈值: 0.60
```

**场景B: 用户请求调整**

```markdown
## 📝 处理您的调整请求

明白了，我会根据您的要求调整任务清单：

**您的调整**:
[总结用户的调整内容]

**调整后的任务清单**:
[展示调整后的清单]

**变更说明**:

- 新增任务: [列出]
- 删除任务: [列出]
- 修改任务: [列出]
- 时间调整: [新的估算]

**请再次确认**:
调整后的清单是否符合您的要求？
```

**场景C: 用户有疑问**

```markdown
## ❓ 解答您的疑问

[针对用户的具体疑问给出解答]

**是否还有其他疑问?**

- 如果疑问已解决，请确认任务清单
- 如果有更多疑问，请继续提出
```

## 相关流程

- **上游**: Phase 0 - generate-todo-list任务
- **下游**: Phase 0 - initialize-todo-tracker任务
- **触发条件**: Todo List生成完成
- **必需确认**: 是（P0级别）

## 注意事项

1. **清晰展示**: 使用视觉符号(✅⏳🔄)增强可读性
2. **时间透明**: 明确告知预计时间
3. **灵活调整**: 允许用户修改任务清单
4. **确认记录**: 保存用户确认作为基线
5. **偏离说明**: 解释Todo List如何用于后续偏离检测

## V4.3特性说明

**Todo List机制**是V4.3的核心创新：

- **执行合同**: 用户确认后形成不可随意偏离的基线
- **偏离检测**: 实时对比执行与基线，相似度<0.60触发告警
- **任务追踪**: 每个任务状态实时更新
- **完成度检查**: Phase 4验证所有任务完成情况
