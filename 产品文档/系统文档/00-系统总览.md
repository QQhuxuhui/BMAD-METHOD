## 🎯 系统简介

### 什么是 APS 模块？

APS (Advanced Planning & Scheduling) 是一个基于 **BMAD-METHOD 规范架构**开发的调度优化专家系统。它通过 **7个专家智能体的协作**，提供从需求分析到代码生成的**端到端调度问题求解能力**。

### 核心特性

#### ✨ V4.3 双模式交互系统
- **模式A（集中确认）**: 20-25分钟，适合专家用户，一次性确认完整模型
- **模式B（增量确认）**: 30-40分钟，适合业务用户，分阶段渐进确认

#### 📋 Todo List 任务规划机制
- Phase 0 自动生成任务清单
- 用户确认形成"执行合同"
- 实时偏离检测（相似度<0.60触发）

#### 🤝 Human-in-the-Loop 人机交互
- 5级触发规则（P0-P4）
- 关键决策点用户确认
- 置信度提升至 0.95

#### 🔒 强约束 Guardrails 策略
- 仅使用：TenElementModel + @专家库 + @知识模块库
- 强制引用路径（citations_required: true）
- 能力缺口 → 报告 → 升级裁决

#### 💾 V4.3 状态持久化系统
- 每个 Phase 强制保存状态文件
- 断点恢复和智能续传
- 状态完整性验证

## 🏗️ 核心概念

### 1. Agent as Doc 理念

**智能体是知识文档的载体，而非知识的替代者**

```
智能体 = 知识文档化载体
专业能力 = 模板化知识模块
工作流程 = 知识模板调用机制
```

每个智能体通过 **Sidecar 模式**按需加载专家知识库，实现 **75-87% 的 Token 节省**。

### 2. TenElementModel（十要素模型）

**统一真相源**，包含调度问题的10个核心要素：

1. **决策变量** - 调度问题中需要确定的变量
2. **参数** - 问题的已知参数和常数
3. **约束** - 必须满足的条件和限制
4. **优化目标** - 需要最小化或最大化的目标函数
5. **算法** - 推荐的求解算法和参数
6. **时间模型** - 时间相关的定义和关系
7. **不确定性** - 随机性和不确定因素的处理
8. **求解配置** - 算法参数、收敛条件、超时设置
9. **输入数据** - 问题输入数据的格式和来源
10. **输出格式** - 解决方案的输出格式和表现形式

TenElementModel 在 **Phase 1.5** 构建并固化，作为所有后续 Phase 的核心依据。

### 3. 7个专家智能体

| 智能体 | 角色 | 核心职责 |
|--------|------|---------|
| 🎯 **系统编排者** | 总指挥 | Phase 0-4编排、专家协调、质量决策 |
| ⚙️ **张效率**（算法专家） | 技术专家 | 算法推荐、性能优化、代码生成 |
| 🔒 **李严谨**（约束专家） | 技术专家 | 约束识别、建模、验证、修复 |
| 🎯 **王目标**（目标专家） | 技术专家 | 目标识别、多目标优化、评估 |
| 🏢 **赵领域**（领域专家） | 业务专家 | 领域识别、业务规则、领域适配 |
| 🔧 **钱扩展**（扩展指导） | 工具专家 | 代码知识提取、模板生成、自动集成 |
| 🛡️ **孙质量**（质量专家） | QA专家 | 语法/逻辑/一致性/基准验证 |

### 4. Phase 0-4 工作流程

```
Phase 0: 任务规划 (5-8分钟)
  ↓ 生成Todo List → 用户确认 → 形成执行合同

Phase 0.5: 双模式交互选择 (2-3分钟)
  ↓ 用户选择模式A或模式B

Phase 1: 需求分析 (10-15分钟)
  ↓ 深度分析 → 偏离检测

Phase 1.5: 十要素建模
  ↓ 模式A: 一次性确认完整模型 (10-15分钟)
  ↓ 模式B: 仅确认框架 (5-8分钟)

Phase 2: 专家协调
  ↓ 模式A: 并行分析 (10-15分钟)
  ↓ 模式B: 增量确认 (31-48分钟)

Phase 3: 方案集成与代码生成 (20-30分钟)
  ↓ 方案融合 → 用户确认 → 代码生成 → 一致性验证

Phase 4: 质量保证 (9-12分钟)
  ↓ 质量门禁(6重) → Todo完成度检查 → 交付确认
```

**总耗时**:
- 模式A: 70-95分钟
- 模式B: 95-130分钟

### 5. 8个专家知识库

采用 **Sidecar 模式**，按需加载，Token 节省率 75-87%：

1. **algorithm-library** - 调度算法（精确/启发式/元启发式）
2. **constraint-library** - 约束模式（容量/时间/空间/逻辑/业务）
3. **objective-library** - 目标优化（时间/成本/质量/效率/可持续性）
4. **domain-library** - 领域应用（车辆/生产/服务/项目/供应链）
5. **orchestrator-library** - 系统编排（协作/决策/集成/风险）
6. **quality-library** - 质量评估（语法/逻辑/一致性/基准/报告）
7. **modeling-library** - 核心建模（十要素/时间/不确定性）
8. **collaboration** - 协作框架（Agent as Doc/知识依赖/协作协议）

## 🔑 关键特性详解

### 强约束策略（Guardrails）

**允许的知识来源**:
```yaml
allowed_sources:
  - TenElementModel        # 十要素模型
  - @专家库/*              # 专家知识库
  - @知识模块库/*          # 通用知识模块
```

**强制要求**:
- `citations_required: true` - 所有输出必须附@引用路径
- 禁止未经引用的推断与发挥
- 禁止超出职责边界的实现与决策
- 禁止虚构算法/约束/目标/领域规则

**能力缺口处理**:
```
检测到缺口 → 输出"能力缺口报告" → 请求补齐模块或升级裁决
```

### Human-in-the-Loop 触发规则

| 级别 | 触发条件 | 示例场景 | 处理方式 |
|------|---------|---------|---------|
| **P0** | Todo List强制要求 | 十要素建模、领域识别、约束确认、目标权重 | 强制人机确认 |
| **P1** | 置信度 < 0.70 | 需求模糊、多种可能方案、缺少关键信息 | 澄清与确认 |
| **P2** | 专家建议冲突 | 算法选择冲突、约束与目标矛盾 | 仲裁与协调 |
| **P3** | 能力缺口 | 特殊领域、罕见约束组合、创新性需求 | 报告并升级 |
| **P4** | 用户主动暂停 | 用户需要思考、咨询他人、准备补充信息 | 恢复与继续 |

### 质量门禁（6重检查）

1. **语法检查** - Python语法正确性
2. **逻辑验证** - 逻辑完整性和正确性
3. **约束一致性** - 代码与TenElementModel一致性
4. **基准评测** - 性能基准测试
5. **引用完整性** - 所有输出包含@引用路径
6. **交付物完整性** - 所有文件已保存且格式正确

## 📁 输出交付物

完整的调度求解流程将产生以下交付物：

### 必需交付物
1. **TenElementModel** (YAML格式) - 问题定义和模型
2. **调度方案文档** (Markdown) - 完整的技术方案
3. **调度方案数据** (YAML) - 结构化方案对象
4. **实现代码** (Python) - 可执行的调度算法
5. **质量报告** (Markdown) - 质量验证结果

### 状态文件（自动保存）
- `phase_0_state.yaml` - Todo基线
- `phase_0_5_state.yaml` - 交互模式配置
- `phase_1_state.yaml` - 需求分析结果
- `phase_1_5_state.yaml` - TenElementModel
- `phase_2_state.yaml` - 专家分析结果
- `phase_3_state.yaml` - 集成方案和代码
- `phase_4_state.yaml` - 质量报告

### 输出目录结构
```
aps-outputs/
├── states/                    # 状态文件（断点恢复）
│   ├── phase_0_state_latest.yaml
│   ├── phase_1_5_state_latest.yaml
│   └── ...
├── models/                    # 模型文件
│   └── ten_element_model_{timestamp}.yaml
├── docs/                      # 方案文档
│   ├── solution_document_{timestamp}.md
│   └── solution_data_{timestamp}.yaml
└── reports/                   # 质量报告
    └── quality_report_{timestamp}.md
```
