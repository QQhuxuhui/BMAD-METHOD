## 触发场景

**触发时机**: Phase 0 任务规划阶段,在 Todo List 确认之后、Phase 1 需求分析之前

**触发条件**:

- 用户首次使用系统
- 用户未在配置中指定默认模式
- 用户明确请求更改交互模式

**目的**:

- 根据用户特征和问题特点,推荐最适合的交互模式
- 让用户理解两种模式的差异和适用场景
- 确保用户做出明智的模式选择

## 对话结构

### 步骤1: 收集用户上下文

**目的**: 评估用户的经验水平、需求清晰度、时间压力等因素

**方式1: 隐式评估**
通过分析用户的需求描述和历史对话,自动推断用户上下文:

```python
user_context = {
    "experience_level": detect_experience_level(conversation_history),
    "requirement_clarity": assess_clarity(user_requirement),
    "complexity": estimate_complexity(problem_features),
    "time_pressure": "unknown"  # 需要询问
}
```

**方式2: 显式询问** (可选,当隐式评估置信度低时)

```markdown
在为您推荐最合适的交互模式前,请简单回答几个问题:

1. 您对调度优化问题的熟悉程度?
   - A. 非常熟悉,有丰富的实践经验
   - B. 了解基本概念,做过一些项目
   - C. 初步了解,需要专家指导

2. 您对本次需求的清晰度自评?
   - A. 非常清晰,需求边界明确
   - B. 基本清晰,部分细节需要探讨
   - C. 还不够清晰,需要逐步明确

3. 本次项目的时间要求?
   - A. 非常紧迫,需要快速出方案
   - B. 有一定时间,希望平衡质量和效率
   - C. 不着急,希望深度探讨每个细节

您可以直接输入 "A1 B2 C3" 或用自然语言描述您的情况。
```

### 步骤3: 处理用户选择

**解析逻辑**:

```python
def parse_mode_selection(user_input: str, recommendation: str) -> dict:
    """
    解析用户的模式选择

    Args:
        user_input: 用户输入
        recommendation: 系统推荐的模式

    Returns:
        解析结果
    """
    # 规范化输入
    input_lower = user_input.lower().strip()

    # 明确选择
    if input_lower in ["1", "模式a", "集中确认", "mode a", "centralized"]:
        return {
            "selected_mode": "centralized",
            "confidence": 1.0,
            "reason": "用户明确选择"
        }

    elif input_lower in ["2", "模式b", "增量确认", "mode b", "incremental"]:
        return {
            "selected_mode": "incremental",
            "confidence": 1.0,
            "reason": "用户明确选择"
        }

    # 采用推荐
    elif input_lower in ["3", "帮我选", "推荐", "自动选择", "auto"]:
        return {
            "selected_mode": recommendation,
            "confidence": 0.95,
            "reason": "采用系统推荐"
        }

    # 请求更多信息
    elif input_lower in ["4", "详细对比", "对比", "比较"]:
        return {
            "action": "show_detailed_comparison",
            "confidence": null
        }

    elif input_lower in ["5", "我有问题", "问题", "咨询"]:
        return {
            "action": "answer_questions",
            "confidence": null
        }

    # 自然语言理解
    else:
        # 关键词匹配
        if any(kw in input_lower for kw in ["快", "时间紧", "赶时间", "效率"]):
            return {
                "selected_mode": "centralized",
                "confidence": 0.80,
                "reason": "用户强调时间效率"
            }

        elif any(kw in input_lower for kw in ["详细", "深入", "慢慢来", "不着急", "学习"]):
            return {
                "selected_mode": "incremental",
                "confidence": 0.80,
                "reason": "用户偏好深度参与"
            }

        else:
            return {
                "action": "clarify",
                "message": "抱歉,我没有理解您的选择。请输入 1-5 或更明确地描述您的偏好。"
            }
```

**记录到系统**:

```python
# 记录到 Todo List
todos.append({
    "phase": "Phase 0",
    "content": f"已选择交互模式: {selected_mode}",
    "status": "completed",
    "metadata": {
        "mode": selected_mode,
        "confidence": confidence,
        "reason": reason,
        "timestamp": datetime.now()
    }
})

# 更新配置
config["interaction_mode"] = selected_mode
config["mode_selection_time"] = datetime.now()
config["mode_confidence"] = confidence

# 记录分析
analytics.log_mode_selection({
    "user_context": user_context,
    "recommendation": recommendation,
    "user_choice": selected_mode,
    "match_recommendation": (selected_mode == recommendation)
})
```

selector = ModeSelector()

## 模式切换机制

### 中途切换模式

如果用户在执行过程中发现当前模式不合适,可以请求切换:

```markdown
用户: /change-mode

系统: |
⚠️ **模式切换确认**

您当前使用的是 **{当前模式}**,已完成:

- Phase 1: 需求分析 ✅
- Phase 1.5: {已完成的部分} ✅
- Phase 2: 进行中...

切换到另一模式需要:

1. 保存当前进度
2. 重新开始 Phase 1.5 (使用新模式的确认方式)
3. 重新执行后续阶段

**确认切换吗?**

1. 是,切换到 {另一模式}
2. 否,继续当前模式
3. 查看当前进度详情

用户: 1

系统: |
✅ **已切换到 {新模式}**

当前进度已保存,我们将从 Phase 1.5 重新开始,使用新的确认方式...
```
