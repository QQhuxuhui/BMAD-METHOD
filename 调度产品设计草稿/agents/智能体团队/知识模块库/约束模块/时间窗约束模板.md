## ⏰ 约束知识本体

### 核心概念

```yaml
时间窗定义:
  早开始时间: EST (Earliest Start Time)
  晚结束时间: LST (Latest Start Time)
  服务时间: ST (Service Time)
  时间窗: [EST, LST-ST]

约束表达:
  硬约束: 必须在时间窗内开始服务
  软约束: 允许轻微违反，但有惩罚
  混合约束: 部分硬约束 + 部分软约束

时间窗类型:
  固定时间窗: 时间范围不可调整
  柔性时间窗: 可以适度调整
  多时间窗: 一个任务有多个可选时间段
  动态时间窗: 时间窗随时间变化
```

### 约束数学模型

```yaml
基本约束:
  设 x_i 为任务i的开始时间
  约束: EST_i ≤ x_i ≤ LST_i - ST_i

软约束惩罚:
  早到惩罚: P_early = α × max(0, EST_i - x_i)
  迟到惩罚: P_late = β × max(0, x_i + ST_i - LST_i)
  总惩罚: P_total = P_early + P_late

时间窗宽度:
  紧时间窗: LST_i - EST_i ≤ ST_i × 1.2
  松时间窗: LST_i - EST_i ≥ ST_i × 2.0
  中等时间窗: ST_i × 1.2 < LST_i - EST_i < ST_i × 2.0
```

## 🔧 约束处理技术

### 时间窗可行性检查

```yaml
前向检查法:
  原理: 从起点开始，逐步检查时间可行性
  步骤: 1. 设置当前时间为起始时间
    2. 对于路径中的每个节点：
    - 计算最早到达时间
    - 检查是否在时间窗内
    - 更新当前时间
    3. 返回可行性判断

  时间复杂度: O(n)
  适用: 序列化任务调度

后向检查法:
  原理: 从终点开始，逆向检查时间可行性
  步骤: 1. 设置当前时间为截止时间
    2. 逆向遍历路径节点：
    - 计算最晚开始时间
    - 检查时间窗约束
    - 更新当前时间
    3. 返回可行性判断

  适用: 有明确截止期限的问题

双向检查法:
  原理: 同时进行前向和后向检查
  优点: 更早发现不可行解
  缺点: 计算复杂度增加
  适用: 复杂约束环境
```

### 时间窗冲突解决

```yaml
时间平移策略:
  延迟执行:
    - 将冲突任务延后执行
    - 检查延迟对后续任务的影响
    - 适用于有时间缓冲的场景

  提前执行:
    - 将任务提前到更早时间窗
    - 考虑等待时间成本
    - 适用于柔性时间窗

任务重排策略:
  局部重排:
    - 重新排列冲突区域的任务
    - 使用局部搜索算法
    - 保持其他区域不变

  全局重排:
    - 重新规划整个序列
    - 使用全局优化算法
    - 计算成本较高

资源调整策略:
  增加资源:
    - 分配额外的服务人员/设备
    - 并行处理冲突任务
    - 考虑资源成本

  任务分割:
    - 将大任务分割为小任务
    - 分散到不同时间窗执行
    - 适用于可分割任务
```

### 软约束处理方法

```yaml
罚函数法:
  线性罚函数: P(v) = w × v
    其中v为违反量，w为权重

  二次罚函数: P(v) = w × v²
    对大违反量惩罚更重

  分段罚函数: P(v) = w1×v (v≤threshold)
    w2×v (v>threshold)
    不同违反程度不同惩罚

模糊约束法:
  模糊隶属函数: μ(x) = 1 (在时间窗内)
    线性递减 (轻微违反)
    0 (严重违反)

  模糊目标: 最大化总的约束满足度
    平衡多个软约束

拉格朗日松弛:
  对偶问题: 将时间窗约束移到目标函数
    通过拉格朗日乘数调整

  迭代求解: 更新拉格朗日乘数
    求解松弛问题
    检查原问题可行性
```

## 📊 约束评估知识

### 时间窗紧张度指标

```yaml
紧张度计算:
  绝对紧张度:
    T_abs = (LST - EST) / ST
    T_abs < 1.5: 非常紧张
    T_abs > 3.0: 相对宽松

  相对紧张度:
    T_rel = (实际用时) / (可用时间)
    T_rel > 0.9: 高度紧张
    T_rel < 0.7: 时间充裕

  系统紧张度:
    T_sys = Σ(紧张任务数) / 总任务数
    评估整体时间压力

冲突概率评估:
  基于历史数据:
    P_conflict = 历史冲突次数 / 总调度次数

  基于时间窗重叠:
    overlap_ratio = 重叠时间 / 总时间窗长度

  基于资源竞争:
    competition_index = 竞争任务数 / 可用资源数
```

### 违反成本评估

```yaml
时间成本:
  等待成本: C_wait = 等待时间 × 单位时间成本

  延迟成本: C_delay = 延迟时间 × 延迟惩罚系数

  加急成本: C_rush = 加急时间 × 加急费率

服务质量成本:
  客户满意度损失: C_satisfaction = f(偏离客户偏好时间)

  服务质量下降: C_quality = g(服务时间压缩比例)

运营成本:
  加班成本: C_overtime = 加班时间 × 加班费率

  资源闲置成本: C_idle = 闲置时间 × 资源成本
```

## 🛠️ 实现算法知识

### 时间窗传播算法

```yaml
前向传播:
  for each task i in sequence:
    earliest_start[i] = max(EST[i],
                          earliest_start[i-1] + duration[i-1] + travel_time)
    if earliest_start[i] > LST[i] - duration[i]:
      return INFEASIBLE

后向传播:
  for each task i in reverse sequence:
    latest_start[i] = min(LST[i] - duration[i],
                         latest_start[i+1] - duration[i] - travel_time)
    if latest_start[i] < EST[i]:
      return INFEASIBLE

时间窗收紧:
  EST[i] = max(EST[i], earliest_start[i])
  LST[i] = min(LST[i], latest_start[i] + duration[i])
```

### 启发式插入算法

```yaml
最佳插入位置:
  for each unscheduled task:
    for each position in current route:
      calculate insertion_cost
      check time_window_feasibility
      if feasible and cost < best_cost:
        best_position = current_position

时间窗检查:
  def check_insertion_feasibility(task, position):
    # 检查插入后的时间可行性
    update_arrival_times(position)
    for each affected_task:
      if violates_time_window(affected_task):
        return False
    return True

成本计算:
  insertion_cost = distance_increase + time_window_penalty
  distance_increase = new_distance - old_distance
  time_window_penalty = waiting_time + delay_penalty
```

### 局部搜索改进

```yaml
2-opt改进:
  for each pair of edges (i,j):
    if swap_improves_solution(i, j):
      if time_windows_remain_feasible(): apply_swap(i, j)

Or-opt改进:
  for each sequence of k consecutive nodes:
    for each insertion position:
      if relocation_improves_solution():
        if time_windows_remain_feasible(): apply_relocation()

时间导向邻域:
  prioritize moves that:
    - reduce time window violations
    - improve time window utilization
    - decrease waiting times
```
